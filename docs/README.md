# README — ドキュメント構成ガイド

**目的: `docs/` 配下のディレクトリ構成・ドキュメント種別・ライフサイクルを定義する。「どこに何を置くか」の正本。**

「どう書くか」(粒度・トーン・書式・判断基準) は `AGENTS.md` を参照すること。用語と固有名詞は `Glossary.md` が一元管理する。


***

## ディレクトリ構成

| パス          | 役割                                                                   |
| ----------- | -------------------------------------------------------------------- |
| `/` (ルート)   | メタ・索引のみ。`README.md` / `AGENTS.md` / `Glossary.md` / `ARCHITECTURE.md` (accepted の ADR を反映した現在のアーキテクチャの索引。詳細は `design/` と `adr/` を参照) |
| `research/` | **技術調査**。Bun・ライブラリ・ブラウザの制約・配布手段などの仕様を、確認日付きで写し取る |
| `design/`   | **確定した設計ドキュメント**。要件、全体設計、トピックごとの設計 (ファイル表示 / Markdown Preview / API / セキュリティ / セッション / データモデル / プロンプト / CLI / 設定 / 画面 / 配布) |
| `plan/`     | **確定した計画ドキュメント**。全体の実装計画と、フェーズごとの詳細計画 (M0〜M7) |
| `adr/`      | Architecture Decision Records (ランタイムの選定・保存方式・配布方式・セキュリティモデルなど後戻りコストの高い決定) |
| `ops/`      | Runbook / Playbook / 手順 (リリース手順など)        |
| `archive/`  | 廃止したドキュメント     |

ライフサイクル:

1. 検討開始時は `research/` に作成
2. 結論が出たら ADR を `adr/` に起票、または確定ドキュメントとして `design/` (設計) / `plan/` (計画) に昇格
3. 廃止になったら `archive/` に移動。削除しない (経緯を残すため)

サブディレクトリは最初のドキュメントを置くときに作成する。空ディレクトリは作らない。
