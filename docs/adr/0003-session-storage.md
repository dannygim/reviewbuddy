# 0003. コメントは ~/.config/akapen にセッション単位の SQLite で保存する

- status: accepted
- date: 2026-10-23

## Context

コメントは対象ディレクトリの外に保存したい (対象のファイルを一切書き換えないため)。同じディレクトリで再起動したら続きから使え、使い終わったものは自動で消えてほしい。コメントは作成のほかに、編集・Resolve・削除がある。

## Decision

**`~/.config/akapen/sessions/<id>/` にセッションごとのディレクトリを作り、`session.json` (メタ情報) と `review.db` (`bun:sqlite`、WAL) を置く。同じルートの active なセッションがあれば再開し、保持期間を過ぎたものは起動時に 2 段階 (終了 → 削除) で消す。**

詳細: [保存先とセッション.md](../design/保存先とセッション.md) / [データモデル.md](../design/データモデル.md)

## Options considered

- **セッションごとの SQLite** (採用): 編集・Resolve・削除が素直に書ける。削除がディレクトリごとで済み、セッション間でロックが干渉しない — DB を直接読むには SQLite が要る (`akapen export` で JSONL に書き出せるようにする)
- **1 つの SQLite に全セッション**: ファイルが 1 つで済む — 削除が行単位になり、1 か所の破損が全体に及ぶ
- **JSONL への追記**: 人が読める — 編集・Resolve・削除が追記で表せず、イベントソーシングにすると読み出しが複雑になる
- **対象ディレクトリ内 (`.akapen/`) に保存**: リポジトリと一緒に持ち運べる — 対象のディレクトリを書き換えることになる

## Consequences

- XDG の流儀 (データは `~/.local/share`) からは外れるが、設定もデータも 1 か所にあり、消すときに迷わない
- `~/.config` を dotfiles として Git 管理している人向けに、`sessions/.gitignore` (中身 `*`) を自動で作る必要がある
- コメントに機密が含まれうるため、ディレクトリは `0700`、ファイルは `0600` で作る
- サーバーの起動中に `akapen export` が同じ DB を読むため、`busy_timeout` を設定する
