# 画面構成

**目的: SPA の画面のレイアウトと、PIN と Nickname の入力・File Tree・行 / ブロックの選択・スレッドの表示・Comment Pane・Review パネル・セッションの終了・Display mode の操作を定める。UI の文言は英語のみとする。**

- 対象の要件: F3 / F4 / F5 / F9 / F10 / F12 / F13 / A3 / A4、非機能要件の「UI」 ([要件.md](./要件.md))
- 対応する調査: [Display_mode_調査.md](../research/Display_mode_調査.md) (Display mode)

***

## レイアウト

```text
+----------------------------------------------------------------------------------------------+
| [=] reviewbuddy ~/work/project  session 20261023-1530     Alice (you), Bob, Carol            |
|                                                    [Review (5)] [End] [Mode]                 |
+-------------------+--------------------------------------------------------------------------+
| v doc/            |  doc/A.md                     [ Preview | Source ]  [Comments]           |
|     A.md      (2) +--------------------------------------------+-----------------------------+
|     B.md      (1) |                                            |                             |
| v src/            |  # Installation                       [+]  | +-------------------------+ |
|     main.ts       |                                            | | Line 3                  | |
| mise.toml     (1) |  Install with mise:                        | | Alice  2m ago           | |
| README.md         |                                            | |   Please state the      | |
|                   |  mise use -g github:...                    | |   required Bun version. | |
|                   |                                            | | Bob    1m ago           | |
|                   |  Body paragraph ...                        | |   1.4 or later is fine. | |
|                   |                                            | | [Reply]  [Resolve]      | |
|                   |                                            | +-------------------------+ |
|                   |  (mermaid fences render as diagrams)       |                             |
+-------------------+--------------------------------------------+-----------------------------+
```

| 領域 | 内容 |
|------|------|
| ヘッダー | File Tree の開閉のボタン (左端、`[=]`)、アプリ名、ルート (ホームは `~` に省略)、セッション ID、接続中の参加者 (自分に `(you)`)、Review ボタン (未解決の数)、End ボタン、Display mode のボタン (右端) |
| 左: File Tree | ツリー順の一覧。ディレクトリは折りたためる。ファイルにスレッドの状態のアイコン (Open は件数付き)、折りたたんだディレクトリに中の Open の印、閲覧中の参加者の頭文字。ヘッダーのボタンで隠せる |
| 中央: Viewer | 選んだファイルの内容。Markdown は `Preview | Source` のタブ。ヘッダーの右端に Comment Pane の開閉のボタン (`[Comments]`) |
| 右: Comment Pane | 開いているファイルのスレッドを、対象の行 / ブロックと同じ高さに並べる ([Comment Pane](#comment-pane))。閉じるとアイコンだけの細い列になる |
| Review パネル | 全ファイルのスレッドの一覧と、プロンプトの生成・コピー |

- 選んだファイルは URL のハッシュ (`#/doc/<path>`) に反映し、リンクで共有できるようにする
- 配色は Display mode で決める。既定の System は OS のライト / ダーク設定に追従する ([Display mode](#display-mode))

## 操作

### PIN と Nickname (F3、[ADR-0007](../adr/0007-access-pin.md))

- Cookie が無いとき (初回、またはサーバーの再起動の後) は、モーダル "Join the review" で Nickname と PIN を一緒に入力してもらう。Nickname は保存済みなら入れておき、PIN の欄にフォーカスする。PIN の欄は `inputmode="numeric"` で、`482 913` のような空白は無視する。間違えるとサーバーのメッセージ ("Wrong PIN." など) を出す
- モーダルの上部、見出しの上に、ロゴ (2 つの吹き出しのマークと、"buddy" をアクセント色にした "reviewbuddy" の文字) を中央寄せで出す。色は CSS の変数で指定し、Display mode に追従する。`role="img"`・`aria-label="reviewbuddy"` を付ける
- PIN を入れるまでは、ファイルの一覧も中身も読み込まない。ヘッダーには "Enter the PIN to join." と出す
- Cookie があれば (同じ起動の間の再読み込み)、PIN は聞かない。Nickname だけが無いときは、モーダル "What should we call you?" で入力してもらう
- Nickname は `localStorage` に保存し、次回からは聞かない
- ヘッダーの自分の名前をクリックすると変えられる
- `client_id` はブラウザごとに 1 回だけ `crypto.getRandomValues()` で作って `localStorage` に保存する

### File Tree (F4)

スレッドの状態は、ファイル名の横の吹き出しのアイコンで示す。吹き出しの形はロゴのマークに合わせる。

| 対象 | 条件 | 表示 | `title` |
|------|------|------|---------|
| ファイル | Open のスレッドがある | アクセント色の塗りの吹き出しと件数 | `<n> open threads` (1 件なら `1 open thread`) |
| ファイル | Resolved のスレッドだけがある | `--muted` の色の線の吹き出し (件数なし) | `Resolved threads only` |
| ディレクトリ | 折りたたんでいて、配下のどこかに Open のスレッドがある | アクセント色の点 | `Open threads inside` |
| ディレクトリ | 展開している | なし (配下のファイルにそれぞれ出る) | - |

- 判定はスレッドの `status` (`open` / `resolved`) だけで行う。Outdated と Sent はスレッドに付く表示なので、File Tree では区別しない

ディレクトリをクリックすると開閉する。折りたたんだディレクトリを展開するときに、その直下に README.md があれば、それも開く。

| 操作 | 直下に README.md がある | ない |
|------|------------------------|------|
| 折りたたんだディレクトリのクリック | 展開して、README.md を開く | 展開する |
| 展開したディレクトリのクリック | 折りたたむ (開いているファイルは変えない) | 折りたたむ |

- 「直下」は、そのディレクトリのすぐ下のファイルに限る。サブディレクトリの中は探さない
- ファイル名は大文字・小文字を区別せずに `readme.md` と比べる。複数が当てはまるとき (大文字・小文字を区別するファイルシステム) は、`README.md` を優先し、なければツリー順で最初のものにする。`README`・`README.rst` など拡張子が違うものは対象にしない
- 開いたファイルを見せるための自動の展開 (共有リンクから開いたときなど) では、README.md を開かない
- 開いているファイルがそのディレクトリの中 (下の階層を含む) にあるときは、展開しても README.md を開かない。折りたたんで戻しただけで画面が移り、書きかけのコメントが消えるのを避けるため
- ファイルを開くのと同じく URL のハッシュを変えるので、ブラウザの「戻る」で前のファイルに戻れる

File Tree はヘッダーの左端のボタンで隠せる。Viewer と Comment Pane を広く使うため。

- ボタンはサイドバーの形のアイコンで、`aria-label="File tree"`。File Tree を出しているときは `aria-pressed="true"`
- 隠すと File Tree の列をなくし、その幅を Viewer に回す。隠して出し直しても、ディレクトリの開閉の状態は変わらない
- 出す / 隠すの状態は `localStorage` の `reviewbuddy.fileTree` (`open` / `closed`) に保存する。ブラウザごとの設定で、サーバーには送らない。値が無いか不正なら `open` として扱う

### 行 / ブロックの選択とスレッドの作成 (F9)

| 表示 | 選び方 |
|------|-------|
| Source 表示 (コード、Markdown の Source) | 行番号のクリックで 1 行、Shift+クリックで範囲を広げる、行番号の上のドラッグで範囲 |
| Preview 表示 (Markdown) | ブロックにホバーすると右端に「+」が出る。クリックでそのブロック (最も内側の `data-src-*` の要素)、Shift+クリックで複数のブロックに広げる |

- 選ぶと、Comment Pane の中の、範囲の先頭の高さに入力欄が開く ([Comment Pane](#comment-pane))。Cmd/Ctrl+Enter で送信、Esc で閉じる
- read-only のセッションでは「+」も入力欄も出さない

### スレッドの表示と操作 (F10)

- 元コメントとリプライを時系列で出す。各コメントに Nickname と相対時刻 (`Intl.RelativeTimeFormat`)
- ボタン: Reply / Resolve (Resolved のスレッドは Reopen)。自分のコメントには Edit / Delete
- Resolved のスレッドは折りたたんで出す。Outdated のスレッドには "Outdated" のラベル、Sent のスレッドには "Sent" のバッジを付ける
- コメントの本文はプレーンテキスト (改行を保持し、URL だけ自動でリンクにする)
- スレッドは Comment Pane に出す ([Comment Pane](#comment-pane))

### Comment Pane

開いているファイルのスレッドを、Viewer の本文の右の列に、対象の行 / ブロックと同じ高さで出す。本文の流れを切らずに、読みながら横でコメントを読み書きできるようにするため (以前は対象の直下に差し込んでいた)。

配置:

- 幅は 360px で固定し、残りを本文にあてる。本文と同じスクロールで縦に動く (スレッドが対象の横から離れないように)
- スレッドのカードの上端を、対象の範囲の先頭に揃える

  | 表示 | 揃える位置 |
  |------|-----------|
  | Source 表示 | 範囲の先頭の行 (`startLine`) の上端。ファイルが短くなってその行が無いときは、最後の行 |
  | Preview 表示 | スレッドが属するブロックの上端。ブロックは、範囲全体を含む最も小さいブロック、無ければ範囲と重なるブロックのうち最も上で始まるもの (同じなら最も小さいもの)。どのブロックにも重ならないスレッドは本文の末尾 |

- カードが重なるときは、揃える位置の上から順に (同じ位置なら作成の古い順) 並べ、前のカードの下端から 8px 空けて下へずらす。ずれたカードも、見出し (`Line 3` / `Lines 9–10`) で対象が分かる
- カードの列が本文より下まで伸びたら、その分だけ下までスクロールできるようにする
- 本文やカードの高さが変わったら (Mermaid の図や画像の読み込み、スレッドの開閉、入力欄の行の増減、ファイルの変更、他の参加者のコメント) 位置を計算し直す
- 長いコードの行は本文の列の中で横にスクロールする。Comment Pane は横には動かない
- 行 / ブロックを選んで開く入力欄も、スレッドと同じ規則で Comment Pane に出す。本文の行の間には差し込まない

アクティブなスレッド (近い行にスレッドが集まると、カードが対象から大きく下にずれ、対象と同じ画面に入らないため。10 件で約 1400px):

- カードをクリックするか、本文でスレッドの対象の行 / ブロックをクリックすると、そのスレッドをアクティブにする。対象が重なる所では、対象の行 / ブロックの数が最も少ないスレッドを選ぶ。スレッドの無い所をクリックすると、アクティブなスレッドを無くす。文字列を選んだだけのときは変えない
- アクティブなカードは揃える位置にそのまま置き、前のカードは上へ (8px 空けて)、後のカードは下へずらす。上へずらしたカードが Comment Pane の上端を越えたら、越えた分は見えない (対象の行 / ブロックをクリックすれば、そのカードが戻る)
- カードの位置が変わるときは、0.3 秒かけて動かす (CSS の `transition`)。返信や画像の読み込みで位置が変わるときも同じ。新しく出たカード (入力欄、開き直した Comment Pane のカード) は、その場に出す
- 入力欄が出ている間は、入力欄をアクティブとして扱う。コメントを送ると、できたスレッドをアクティブにする
- アクティブなカードは枠をアクセント色にし、対象の行 / ブロックの背景を `--selected` の色にする。カードにマウスを乗せている間も、そのスレッドの対象を同じ色にする
- カードのクリックでアクティブにしたときは、カードが対象の横へ動いた後、カードが画面に入るようにスクロールする (Viewer のヘッダーに隠れないように)
- どのスレッドがアクティブかは保存しない。Preview / Source の切り替えで無くなる

開閉:

- Viewer のヘッダーの右端 (`Preview | Source` のタブの右) に、吹き出しのアイコンのボタンを置く。`aria-label="Comments"`。開いているときは `aria-pressed="true"`
- 閉じると幅 28px の細い列になり、スレッドのある高さに吹き出しのアイコンだけを出す。色と形は File Tree と同じ (Open はアクセント色の塗り、Resolved は `--muted` の色の線)。`title` はスレッドの見出し (`Line 3` など)。重なりの規則はカードと同じ
- 閉じた列のアイコンをクリックすると、Comment Pane を開き、そのスレッドをアクティブにする
- 閉じているときに行 / ブロックを選ぶと、Comment Pane を開いて入力欄を出す
- 開閉の状態は `localStorage` の `reviewbuddy.commentPane` (`open` / `closed`) に保存する。ブラウザごとの設定で、ファイルを移っても変わらない。値が無いか不正なら `open` として扱う
- 画像とバイナリのファイルはコメントできないので、Comment Pane もボタンも出さない
- read-only のセッションでも出す (スレッドは読める)
- Review パネルは今と同じく、Comment Pane の上に重ねて出す

### Review パネル (F12 / A3)

- フィルタ: Open / Resolved / Sent
- 各スレッドにチェックボックス (既定: 未解決すべてに付く)。クリックすると該当のファイルと行に移る
- "Copy prompt" でプロンプトを生成してコピーする ([プロンプト出力仕様.md](./プロンプト出力仕様.md))。"Resolve copied threads" のチェックボックスを横に置く

### セッションの終了 (F13)

- End ボタンで確認のモーダルを出す。モーダルには「先にプロンプトをコピーする」「JSONL を書き出す (`reviewbuddy export --format jsonl`)」の案内を出す
- 終了すると全員の画面の上部に "This session has ended. Comments are read-only." のバナーを出す

### プレゼンス (A4)

- ヘッダー: 接続中の参加者の Nickname (自分が先頭)
- File Tree: 各ファイルの横に、そのファイルを開いている参加者の頭文字の丸 (ホバーで Nickname)

### Display mode

画面の配色を Light / Dark / System から選ぶ。既定は System (OS のライト / ダーク設定に追従する)。

- ヘッダーの右端に、今のモードのアイコンのボタンを置く (Light = 太陽、Dark = 月、System = モニター)。`aria-label` は `Display mode: <モード>`
- ボタンで `popover="auto"` のメニューを開く。項目は Light / Dark / System の 3 つで、`role="menu"` の中の `role="menuitemradio"` とし、選んでいるモードに `aria-checked="true"` と ✓ を付ける
  - 開いたら選んでいる項目にフォーカスする。上下の矢印キーで項目を移り (端では反対の端へ回る)、Enter / Space で選ぶ
  - 選ぶとメニューを閉じる。Esc と外側のクリックで閉じるのはブラウザに任せる (light dismiss)
  - メニューはヘッダーの直下・右端に CSS で固定して出す
- 選んだモードは `localStorage` の `reviewbuddy.displayMode` (`light` / `dark` / `system`) に保存する。ブラウザごとの設定で、サーバーには送らず、他の参加者には影響しない。値が無いか不正なら `system` として扱う
- 反映の仕組み ([Display_mode_調査.md](../research/Display_mode_調査.md)):
  - Light / Dark では `<html>` に `data-display-mode="light"` / `"dark"` を付ける。System では付けない
  - CSS は `:root` を `color-scheme: light dark` とし、属性があれば `light` / `dark` に固定する。色の変数は `light-dark(<ライト>, <ダーク>)` で 1 か所に定義し、`prefers-color-scheme` のメディアクエリは使わない
  - 保存したモードは、最初の描画の前に `index.html` の `<head>` のインラインの script で反映する。`main.tsx` は module script で描画を止めないため、バンドルが届くまで反対の配色が見えてしまう ([Display_mode_調査.md](../research/Display_mode_調査.md))。`main.tsx` の `initDisplayMode()` も同じ属性を付け、モジュールの状態を保存値に合わせる
- 対象は画面の色、コードのハイライト ([ファイル一覧と表示.md](./ファイル一覧と表示.md))、Mermaid の図 ([Markdown_Preview.md](./Markdown_Preview.md)) のすべて
- PIN の入力のモーダルが開いている間は、モーダルの背景がヘッダーを覆うため、マウスでは切り替えられない (保存したモードは適用される)

### ファイルの変更 (A1)

- 開いているファイルが変わったら、スクロール位置を保ったまま内容を取り直す
- 変わったファイルがツリーの中にあれば、名前を短い間強調する
