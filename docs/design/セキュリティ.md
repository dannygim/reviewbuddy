# セキュリティ

**目的: 手元のサーバーがソースコードを配信するという前提で、最低限守る対策と、その理由を定める。**

- 対応する調査: [ブラウザ制約_Tailscale_調査.md](../research/ブラウザ制約_Tailscale_調査.md) / [Bun_調査.md](../research/Bun_調査.md)
- 対応する ADR: [ADR-0007](../adr/0007-access-pin.md) (起動ごとの PIN。[ADR-0006](../adr/0006-security-without-auth.md) を置き換え)
- 前提: 通話などでその場にいる相手と URL と PIN を共有して使う。PIN を知る人どうしは信頼し、Nickname は自己申告 ([要件.md](./要件.md))

***

## 想定する脅威と対策

| 脅威 | 例 | 対策 |
|------|----|------|
| URL に届く第三者の閲覧と書き込み | 同じ tailnet の他の人、`--host 0.0.0.0` での LAN の人、Funnel で公開した場合はインターネットの誰でも | 起動ごとの 6 桁の PIN を入力したブラウザにだけ Cookie を渡し、API と WebSocket で必須にする。失敗の回数に上限を設ける |
| ルートの外のファイルの読み出し | `GET /api/file?path=../../.ssh/id_rsa`、ルートの外を指すシンボリックリンク | FileIndex に含まれるパスだけを配信する。realpath がルートの外になるものは拒否する |
| DNS rebinding | 悪意あるサイトが自分のドメインを `127.0.0.1` に向け直し、同一オリジンとして `/api/file` を読む | `Host` ヘッダーの許可リスト |
| CSRF | 悪意あるサイトから `POST /api/threads` を送り、コメントを書き込む | 書き込み API はトークンを必須にする + `Content-Type: application/json` のみ受け付ける |
| Cross-Site WebSocket Hijacking | 悪意あるサイトから `ws://127.0.0.1:4400/ws` に接続し、コメントを盗み見る | WebSocket の接続にトークンを必須にする + upgrade の前に `Origin` を検証する |
| Markdown 経由の XSS | Markdown 中の `<script>`、`javascript:` のリンク、悪意ある SVG | DOMPurify によるサニタイズ、Mermaid の `securityLevel: 'strict'`、画像の配信に CSP の `sandbox` |
| コメント経由の XSS | コメント本文に HTML を書く | コメント本文はプレーンテキストとして表示する (改行の保持と URL の自動リンクのみ) |
| 秘密情報の取り込み | レビュー対象のプロジェクトの `.env` が reviewbuddy の環境変数に入る | ビルドに `--no-compile-autoload-dotenv --no-compile-autoload-bunfig` を付ける |
| 保存データの盗み見 | 同じマシンの他のユーザーが `~/.config/reviewbuddy/` を読む | ディレクトリは `0700`、ファイルは `0600` で作る |

***

## 対策の詳細

### アクセスの PIN

- 起動するたびに、`crypto.getRandomValues` で `000000`〜`999999` を一様に作る (2^32 を 100 万で割った余りが偏らないよう、端数の範囲は引き直す)。ターミナルに URL と並べて `PIN: 482 913` と表示する。プロセスのメモリにだけ持ち、ファイルには書かない
- `POST /api/login` に `{ "pin": "482913" }` を送る (空白は無視する)。比較は定数時間で行う。正しければランダムなトークン (32 バイト、16 進) を作ってメモリに覚え、Cookie で返す
- Cookie の名前は `reviewbuddy_auth_<待ち受けているポート>`、属性は `HttpOnly; SameSite=Strict; Path=/`。Cookie はポートで分かれないため、名前にポートを含めて、同じホストで動く別の reviewbuddy の Cookie を上書きしないようにする
- `/api/*` と `/ws` は Cookie が必要で、無いか知らないトークンなら `401` を返す (`Host` の確認の後、トークンの確認の前)。例外は `POST /api/login` と `GET /api/health` (多重起動の判定に使うため。アプリ名・版・セッション ID だけを返し、ルートのパスは返さない)。SPA の HTML と JS・CSS はデータを含まないので Cookie なしで配る
- 失敗は、全員の合計で 1 分あたり 5 回まで (超えたら `429`)。`tailscale serve` を通すとすべての接続元が `127.0.0.1` になるため、接続元ごとには数えない。プロセス全体で 20 回失敗したら、以後のログインをすべて `403` で拒否し、ターミナルに `reviewbuddy: too many wrong PINs; restart reviewbuddy to get a new PIN.` を出す。20 回で当てられる確率は 0.002%
- 再起動するとトークンは消えるので、全員がもう一度 PIN を入力する。画面は WebSocket が切れたときに `GET /api/session` を確かめ、`401` ならログインの画面に戻る
- HTTP の直接の接続 (`--host 0.0.0.0`) では PIN と Cookie が平文で流れる。`tailscale serve` (HTTPS) を推奨する
- 第三者がわざと 20 回間違えると、正しい参加者も入れなくなる (再起動で戻る)。Funnel でインターネットに公開する場合に起こりうるが、受け入れる

### `Host` ヘッダーの許可リスト

すべてのリクエストで `Host` ヘッダーのホスト名を確かめ、次のどれでもなければ `403` を返す。

- IP アドレスのリテラル (`127.0.0.1`、`100.x.y.z`、`[::1]` など)。DNS rebinding はドメイン名を使うため、IP リテラルは安全
- `localhost`
- `.ts.net` で終わる名前 (`tailscale serve` の HTTPS の名前。DNS は Tailscale が管理しているため、第三者が向け直せない)
- 設定ファイルの `server.allowed_hosts` に書いた名前 (MagicDNS の短い名前などを使う場合。[設定ファイル.md](./設定ファイル.md))

### 書き込みと WebSocket のトークン

- サーバーは起動するたびにランダムなトークン (32 バイト、16 進) を作る
- SPA は起動時に `GET /api/session` でトークンを受け取る。他のオリジンのページはこの応答を読めない (CORS のヘッダーを返さないため)
- 書き込み API (`POST` / `PATCH` / `DELETE`) は `X-Reviewbuddy-Token` ヘッダーを必須にし、一致しなければ `403` を返す。独自ヘッダーと `application/json` は CORS のプリフライトを起こすため、他のオリジンからは送れない
- WebSocket は `/ws?token=<token>` で接続する。一致しなければ upgrade しない
- 加えて、WebSocket の upgrade の前に `Origin` を確かめる。`Origin` がある場合は、そのホストが `Host` ヘッダーと一致するか、`.ts.net` で終わるときだけ許す (Bun のドキュメントの推奨)

### パスの検証

- API が受け取るパスは、FileIndex に含まれるものだけを受け付ける (`..` を含むパスや絶対パスは一覧に存在しないため、自然に弾かれる)
- 読み出す前に realpath を求め、ルートの外ならシンボリックリンク経由でも拒否する
- 該当しない場合は、存在の有無を区別せず `404` を返す

### 配信するコンテンツ

- サーバーが返す HTML (Shiki / markdown-it の出力) は、クライアントで DOMPurify を通してから DOM に入れる ([Markdown_Preview.md](./Markdown_Preview.md))
- `GET /api/raw` (画像) は `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox` と `X-Content-Type-Options: nosniff` を付ける。SVG を直接開かれてもスクリプトが動かないようにするため

## テスト観点

- Cookie なしでは `/api/tree` などと書き込み (トークンがあっても) が `401`、WebSocket の upgrade が拒否される。`/` と `/api/health` は通り、`/api/health` はルートを返さない
- 正しい PIN で `reviewbuddy_auth_<port>` の Cookie が返り、それで API と WebSocket が通る。間違いは `401`、形式違いは `400`
- 1 分あたり 5 回の上限と 1 分後の回復、通算 20 回で正しい PIN も `403` になる
- `Host: evil.example` のリクエストが `403`、`Host: 127.0.0.1:4400` / `localhost:4400` / `mac.tail1234.ts.net` が通る
- トークンなし・不一致の書き込みが `403`
- トークンなし・不一致、または `Origin` が別のサイトの WebSocket の upgrade が拒否される
- `../` を含むパス、ルートの外を指すシンボリックリンク、一覧に無いファイルが `404`
- 作成したディレクトリとファイルのパーミッションが `0700` / `0600`
- `GET /api/raw` の応答に CSP の `sandbox` が付く
