# 要件

**目的: reviewbuddy v1 の機能要件・追加機能・非機能要件・スコープ外を 1 か所にまとめ、各要件を実現する設計書へつなぐ。要件 ID (F / A) は計画書・テストからの参照に使うため変えない。**

***

## 概要

reviewbuddy は、対象ディレクトリのドキュメントとコードを複数人がブラウザで閲覧し、行・ブロック単位でコメントとリプライを付け、そのスレッドを Coding Agent 向けのプロンプトとしてコピーするための CLI / Web アプリである。

```sh
reviewbuddy .   # カレントディレクトリをルートとして起動し、表示された URL をブラウザで開く
```

***

## 機能要件

| ID | 要件 | 実現方法 (概要) | 設計書 |
|----|------|----------------|--------|
| F1 | Bun で動く CLI。カレントディレクトリか、引数で指定したディレクトリをルートとして起動する | `reviewbuddy [dir]`。引数は `node:util` の `parseArgs` で処理する。起動時に URL を表示し、`--open` でブラウザも開く | [CLI_仕様.md](./CLI_仕様.md) |
| F2 | ブラウザから Web アプリにアクセスする | `Bun.serve` の `routes` に HTML import を渡し、SPA と API を同じプロセスで配信する | [全体設計.md](./全体設計.md) |
| F3 | 初回アクセス時に Nickname を入力する | モーダル ("What should we call you?") で入力 → `localStorage` に保存 (ヘッダーから変更できる)。WebSocket の接続時にサーバーへ送り、参加者一覧に出す | [画面構成.md](./画面構成.md) |
| F4 | 左に File Tree を出す (全ファイル・ディレクトリ。`.gitignore` の対象は出さない) | `git ls-files` の結果からツリーを作る。各ファイルにスレッドの状態のアイコン (Open は件数付き) を付け、折りたたんだディレクトリには配下の Open を印で示す。ディレクトリを展開すると、直下の README.md を開く。ヘッダーのボタンで隠せる | [ファイル一覧と表示.md](./ファイル一覧と表示.md) / [画面構成.md](./画面構成.md) |
| F5 | ファイルを選ぶと、右ペインに内容を出す | `GET /api/file?path=` でレンダリング済みの HTML と行の配列を返す。URL ハッシュ (`#/doc/A.md`) に反映し、リンクで共有できるようにする。ファイルを選んでいないときは、ルートの直下の README.md を開く | [ファイル一覧と表示.md](./ファイル一覧と表示.md) |
| F6 | Markdown は Preview で表示する | markdown-it でサーバー側でレンダリングし、各ブロック要素に元ファイルの行範囲を付ける | [Markdown_Preview.md](./Markdown_Preview.md) |
| F7 | Markdown 中の Mermaid は図として表示する | 言語 `mermaid` のフェンスを `<div class="mermaid">` に変換し、クライアントで Mermaid を実行する | [Markdown_Preview.md](./Markdown_Preview.md) |
| F8 | Markdown 以外はコードハイライトのみ (GitHub 風) | Shiki (`github-light` / `github-dark` のデュアルテーマ) + 行番号のガター | [ファイル一覧と表示.md](./ファイル一覧と表示.md) |
| F9 | 行を選んでコメントする (単一行・範囲) | Source 表示: 行番号のクリック / Shift+クリック / ドラッグ。Preview 表示: ブロックにホバーすると「+」が出て、段落・見出し・リスト項目・表の行・Mermaid の図・コードブロック単位でコメントする。Shift+クリックで複数のブロックに広げる | [画面構成.md](./画面構成.md) |
| F10 | 参加者全員でコメント・リプライする | スレッド = 元コメント + リプライ。作成・編集・削除・Resolve / Reopen を WebSocket で全員へ即時に配信する | [API.md](./API.md) |
| F11 | コメントをセッション単位で永続化する | `~/.config/reviewbuddy/sessions/<id>/review.db` (`bun:sqlite`、WAL)。同じルートで再起動すれば同じセッションを再開する | [保存先とセッション.md](./保存先とセッション.md) / [データモデル.md](./データモデル.md) |
| F12 | Coding Agent 向けのプロンプトを生成してコピーする | Review パネルで対象のスレッドを選び (既定: 未解決すべて)、決まった形式で生成してクリップボードへ。CLI からも `reviewbuddy export` で出力できる | [プロンプト出力仕様.md](./プロンプト出力仕様.md) |
| F13 | セッションを終了・削除する | UI の End session / `reviewbuddy session end` で終了する (以後 read-only)。保持期間を過ぎたら起動時に自動で削除する。手動の削除コマンドもある | [保存先とセッション.md](./保存先とセッション.md) |

## 追加機能 (v1 に含める)

| ID | 要件 | 理由・実現方法 | 設計書 |
|----|------|---------------|--------|
| A1 | ファイル変更の監視とライブ更新 | Agent がファイルを直した結果を、ブラウザの再読み込みなしで確かめたい。`fs.watch` (recursive) + デバウンス → WebSocket で `file.changed` / `tree.changed` を通知する | [ファイル一覧と表示.md](./ファイル一覧と表示.md) |
| A2 | コメント位置の追従と Outdated 表示 | ファイルが変わると行番号がずれる。作成時の選択行のテキストを保存しておき、近くから探し直して行番号を更新する。見つからなければ Outdated にする (GitHub の PR と同じ考え方) | [データモデル.md](./データモデル.md) |
| A3 | 送信済みの区別 | プロンプトとしてコピーしたスレッドに `exported_at` を記録し、「Sent」バッジを出す。コピー時にまとめて Resolve するオプションもある | [プロンプト出力仕様.md](./プロンプト出力仕様.md) |
| A4 | プレゼンス表示 | ヘッダーに接続中の参加者、File Tree に「誰がどのファイルを見ているか」を出す | [画面構成.md](./画面構成.md) |

## 非機能要件

| 区分 | 要件 |
|------|------|
| UI | 英語のみ (i18n の仕組みは入れない)。配色はヘッダーの Display mode で Light / Dark / System から選ぶ (既定は System = OS のライト / ダーク設定に追従。ブラウザごとに保存。[画面構成.md](./画面構成.md))。コメント本文の言語は自由 |
| 実行環境 | Bun 1.4 系以上。macOS (Apple silicon) が主対象、Linux は動作確認のみ。Windows は v1 の対象外 |
| 配布 | GitHub Releases の単一バイナリを mise で入れる ([配布.md](./配布.md)) |
| 待ち受け | 既定は `127.0.0.1:4400` (使用中なら次の空きポート)。`--host` / 設定ファイルで変えられる。リモート共有の手段はツールの責務外とし、README で `tailscale serve` による HTTPS 化を推奨として案内する |
| 規模 | 同時接続は 10 人程度、ファイル数は 2 万程度で、ツリーの表示が 1 秒以内 |
| 読み取り専用 | 対象ディレクトリのファイルは一切書き換えない。書き込むのは `~/.config/reviewbuddy/` の配下のみ |
| セキュリティ | 信頼できる同僚との tailnet 内の利用が前提でも、最低限は守る ([セキュリティ.md](./セキュリティ.md)) |
| 認証 | アカウントはなし。起動ごとの 6 桁の PIN を入力した人だけが使える ([ADR-0007](../adr/0007-access-pin.md))。Nickname は自己申告 |
| バイナリ / 巨大ファイル | 画像は `<img>` でプレビューする。その他のバイナリは "Binary file not shown"。2MB 超 (設定可) はハイライトなしで表示する |

***

## スコープ外 (v1)

- ファイルの編集・保存 (閲覧とコメントのみ)
- リモートアクセス・アカウントによる認証・HTTPS の終端 (Tailscale などに任せる)
- Git の diff 表示・コミット単位のレビュー (v2 候補)
- Coding Agent との直接連携 (MCP サーバー、Claude Code スキル、Agent からスレッドへの返信) (v2 候補)
- 英語以外の UI、プロジェクト単位の設定ファイル (v2 候補)
- `tailscale serve` の ID ヘッダー (`Tailscale-User-Login`) による Nickname の自動入力 (v2 候補)
- 複数ルートディレクトリの同時オープン、サブモジュールの内部の展開、Windows
