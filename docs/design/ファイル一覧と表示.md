# ファイル一覧と表示

**目的: File Tree に出すファイルの選び方、ファイル内容の表示方法 (ハイライト・画像・バイナリ・巨大ファイル)、ファイル変更の監視を、実装とテストの粒度で定める。**

- 対応する調査: [gitignore_判定_調査.md](../research/gitignore_判定_調査.md) / [レンダリング_調査.md](../research/レンダリング_調査.md)
- 対象の要件: F4 / F5 / F8 / A1、非機能要件の「バイナリ / 巨大ファイル」 ([要件.md](./要件.md))
- Markdown の Preview は [Markdown_Preview.md](./Markdown_Preview.md) に分ける

***

## ファイル一覧 (FileIndex)

### 一覧の作り方

| 状況 | 方法 |
|------|------|
| ルートが Git リポジトリの中 | `git -C <root> ls-files --cached --others --exclude-standard -z` の結果から、作業ツリーに存在しないもの (削除済みだが index に残っているもの) を除く |
| Git 管理外 / `git` コマンドが無い | ルートから走査し、各階層の `.gitignore` を `ignore` で積み上げて判定する |

- 追跡済み + 未追跡だが除外されていないファイルを出す。`.gitignore` / `.git/info/exclude` / `core.excludesFile` で除外されたものは出さない
- `.gitignore` に該当しても `git add -f` 済みの追跡ファイルは出す (Git の管理下なので正しい挙動)
- ルートがリポジトリのサブディレクトリでも、`git -C` の出力はルートからの相対パスになる
- **常に出さない**: `.git/`、および設定ファイルの `viewer.exclude` に書いたパターン ([設定ファイル.md](./設定ファイル.md))
- 空のディレクトリは出さない (Git と同じ)
- サブモジュールは gitlink の 1 エントリとして出し、中は展開しない

### パスの表現と並び順

- パスはルートからの相対パス・POSIX 区切り (`doc/A.md`)
- **ツリー順**: パスをセグメントごとに比べ、同じ階層ではディレクトリをファイルより先にする。同じ種類どうしは名前の大文字・小文字を区別せずに比べ、同じなら区別して比べる。File Tree の表示と、プロンプトの並び順 ([プロンプト出力仕様.md](./プロンプト出力仕様.md)) の両方でこの順序を使う

### API

- `GET /api/tree` → ツリー順に並べたファイルのパスの配列。ツリーの組み立てはクライアントで行う ([API.md](./API.md))

## ファイルの表示

### 種類の判定

| 種類 | 判定 | 表示 |
|------|------|------|
| `markdown` | 拡張子 `.md` / `.markdown` | Preview 表示 (既定) と Source 表示を切り替える ([Markdown_Preview.md](./Markdown_Preview.md)) |
| `image` | 拡張子 `.png` / `.jpg` / `.jpeg` / `.gif` / `.webp` / `.svg` / `.ico` / `.bmp` / `.avif` | `GET /api/raw?path=` を `<img>` で表示する |
| `binary` | 先頭 8KB に NUL バイトを含む | "Binary file not shown" |
| `large` | `viewer.max_highlight_bytes` (既定 2,000,000 バイト) を超える | ハイライトなしのプレーンテキスト + 行番号 |
| `code` | 上記以外 | Shiki でハイライト + 行番号 |

### コードのハイライト

- Shiki の `codeToHtml` に `themes: { light: "github-light", dark: "github-dark" }` を渡してデュアルテーマで出す。切り替えは CSS 変数 (`--shiki-dark`) と `prefers-color-scheme` で行う
- 出力の 1 行 = `<span class="line">` 1 つ。クライアントはこれに行番号のガターと行選択を付ける
- 読み込むのは `shiki/core` と、対応表に載せた言語だけにする (バイナリのサイズを抑えるため。全言語だと約 114MB)
- 言語の決め方: ファイル名の完全一致 (`Dockerfile` → `docker`、`Makefile` → `make`、`mise.toml` → `toml`、`.env` / `.env.*` → `dotenv`) → 拡張子 → 不明なら `text`
- 結果は `(path, mtime, size)` をキーにメモリにキャッシュする

### 応答の形

`GET /api/file?path=` は、種類 (`kind`)、元のテキストの行の配列 (`lines`。`binary` / `image` では空)、表示用の HTML (`html`。`code` / `markdown` のみ)、`mtime` を返す。型の正本は `src/shared/` に置く ([API.md](./API.md))。

## ファイルの監視 (A1)

- `fs.watch(root, { recursive: true })` で監視する。`--no-watch` で無効にできる
- イベントは 200ms でデバウンスしてまとめる
- 一覧に含まれるファイルの変更 → キャッシュを捨て、`file.changed` を配信し、そのファイルのスレッドを再アンカーする ([データモデル.md](./データモデル.md))
- 一覧に無いパスのイベント (追加・削除の可能性) → FileIndex を作り直し、前回と違えば `tree.changed` を配信する
- `.git/` の中のイベントは、index の更新 (`git add` など) を拾うために FileIndex の作り直しだけを行う

## テスト観点

- [gitignore_判定_調査.md](../research/gitignore_判定_調査.md) の 7 ケースを、一時ディレクトリに作ったリポジトリでそのまま確かめる
- Git 管理外のディレクトリで、ネストした `.gitignore` が積み上がる
- `viewer.exclude` と `.git/` が常に除外される
- ツリー順: `b/`、`A.md`、`a.md`、`c/d.md` などを混ぜたときの順序
- 種類の判定: 画像の拡張子、NUL を含むファイル、閾値ちょうど / 超えのサイズ
- 言語の決め方: `Dockerfile`、`mise.toml`、`.env.local`、未知の拡張子
- 監視: ファイルを書き換えると `file.changed`、追加すると `tree.changed` が届く (macOS / Linux)
- 2 万ファイルの生成リポジトリで、`/api/tree` の応答とツリーの描画が合わせて 1 秒以内
