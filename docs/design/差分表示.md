# 差分表示

**目的: 未コミットの変更 (HEAD と作業ツリーの差) と、選んだブランチとの差を、GitHub の Pull Request の Files changed と同じ形で見せる Changes 画面について、差分の取り方・表示・コメント・Viewed・ライブ更新を、実装とテストの粒度で定める。**

- 対応する調査: [git_差分_調査.md](../research/git_差分_調査.md)
- 対象の要件: A5 ([要件.md](./要件.md))
- 画面の配置は [画面構成.md](./画面構成.md)、API は [API.md](./API.md) を参照

***

## 方針

- 変更前の側は、既定では HEAD とする。Changes 画面の上部でブランチを選んだら、そのブランチと HEAD の分岐点 (merge base) とする ([比較の基準](#比較の基準))
- 変更後の側は、常に今の作業ツリーとする。コメントを今のファイルの行 (変更後の行番号) にひも付けるため
- ステージ済みかどうかは区別しない。Agent の変更を確かめる用途では区別が要らないため
- 参加者は各自のペースで見て回る前提とする。そのため Viewed はブラウザごとに持ち、他の参加者には共有しない
- コメントは今のスレッドの仕組みをそのまま使う。データモデルは変えない ([データモデル.md](./データモデル.md))

### 方式の比較

| 方式 | 内容 | 採否 |
|------|------|------|
| `git diff-index` (plumbing) の hunk + 自前の単語・ブロックの差分 | 行の差分は git に任せ、行の中の単語と Markdown のブロックの突き合わせだけを自前の Myers で行う | 採用。index に書き込まず、行の差分は git と同じになる |
| `git diff` (porcelain) の出力を読む | 最も手軽 | 不採用。`--no-optional-locks` でも `.git/index` を書き換える ([git_差分_調査.md](../research/git_差分_調査.md)) |
| 行の差分もすべて自前で計算する | git は一覧と元の内容の取り出しだけに使う | 不採用。`git diff` と結果がずれうる。大きなファイルでは遅い |
| 差分のライブラリ (jsdiff など) を足す | 実装が減る | 不採用。依存を増やさない方針 (ADR-0001)。必要な Myers は小さい |

### ブランチとの比べ方

| 方式 | 内容 | 採否 |
|------|------|------|
| 分岐点 ↔ 作業ツリー | `merge-base <ブランチ> HEAD` と作業ツリーを比べる。ブランチでコミットした変更と未コミットの変更がまとめて出る | 採用。変更後の側が今のファイルなので、コメントも Viewed も既定と同じ仕組みで動く。`diff-index` に渡すコミットを変えるだけで済む |
| 分岐点 ↔ HEAD | GitHub の Pull Request と同じく、コミットした変更だけを出す | 不採用。未コミットの変更があると変更後の側が今のファイルと違い、変更後の行番号へのコメントがずれる |
| ブランチの先端 ↔ 作業ツリー | `diff-index <ブランチ>` (two-dot) | 不採用。分かれた後にブランチ側へ入った変更が、逆向きの変更として混ざる |

## 比較の基準

変更前の側のコミットを「比較の基準」と呼ぶ。既定は HEAD、Changes 画面の上部の `Compare with` で選んだブランチがあれば、その分岐点とする。

### 選べるブランチ

- `GET /api/branches` が、`for-each-ref --format=%(refname)%00%(refname:short)%00%(symref)%00%(HEAD) refs/heads refs/remotes` のローカルブランチとリモート追跡ブランチを、短い名前 (`main`、`origin/main`) で返す
- 今のブランチ (`%(HEAD)` が `*`) と symref (`origin/HEAD` など) は除く。今のブランチとの分岐点は HEAD 自身で、既定と同じになるため
- タグや任意のコミットは選べない

### 基準のコミット

- ブランチは `?base=<短い名前>` で受け取る。今の `GET /api/branches` の一覧にある名前だけを受け付け、無ければ `404` (`No branch named <名前>.`)。git にはフルの refname (`refs/...`) を渡す (利用者の入力を、git のオプションやリビジョンの式として読ませないため)
- 基準のコミットは `merge-base <refname> HEAD`。得られない (共通の祖先が無い・HEAD が無い) ときは `400` (`No common ancestor with <名前>.`)
- merge base が複数あるとき (criss-cross merge) は、`merge-base` が出す 1 つを使う

### 画面

- `Compare with` のプルダウン (`<select>`) を、Changes 画面の上部の左端に置く。項目は `HEAD (uncommitted)` (既定)、`Local` と `Remote` のグループ
- 選んだブランチは URL のハッシュ `#/changes?base=<名前>` に反映する (履歴は積まない)。再読み込みで残り、リンクで共有できる。参加者どうしでは共有しない (各自のペースで見るため)
- `Files` に行って `Changes` に戻ると、直前に選んだブランチに戻る。ヘッダーの `Changes` の数も、直前に選んだ基準での数
- URL のブランチが一覧に無い (消えた) ときも、その名前を項目に残して選んだ状態を示す。比べられないときは、カードの代わりにサーバーのメッセージを出す
- 変更が無いときは、既定は `No uncommitted changes.`、ブランチを選んでいるときは `No changes against <名前>.`

## 変更のあるファイルの一覧

ルートが Git の作業ツリーの中でなければ、Changes 画面は出さない (`GET /api/changes` が `git: false` を返す)。

git のコマンドはすべて `git --no-optional-locks -C <root>` で実行する。下の `<基準>` は[基準のコミット](#基準のコミット) (既定は HEAD)。

| 対象 | 取り方 | 状態 |
|------|--------|------|
| 追跡済みのファイル | `diff-index <基準> -M --relative --numstat -z` に出たもの。状態と基準の blob は `diff-index <基準> -M --relative --raw -z` の同じパスの文字と変更前の blob | `A` = added、`D` = deleted、`R` = renamed、それ以外 = modified |
| 未追跡のファイル | `ls-files --others --exclude-standard -z` | added |
| HEAD が無い (最初のコミットの前。既定の基準のとき) | FileIndex のすべてのファイル | added |

- `--numstat` に出ないもの (`touch` されただけのファイル) は出さない
- 削除以外は FileIndex に載っているファイルだけを出す (`.gitignore`・`viewer.exclude`・サブモジュールの扱いを File Tree と同じにするため)。削除されたファイルは `viewer.exclude` に当たらなければ出す
- インデックスから外したが作業ツリーに残したファイル (`git rm --cached`) は、Git には削除と未追跡の両方として出る。基準と作業ツリーだけを比べるため、1 つの modified として基準の内容と比べ、同じなら出さない
- シンボリックリンクは、Git と同じくリンク先のパス (リンクの中身) を比べる。リンク先のファイルは読まない (ルートの外を指していても、その内容が行数やハッシュに出ないようにするため)
- 追加・削除の行数は `--numstat` の値を使う。未追跡のファイル・HEAD が無いとき・インデックスから外したファイルは、行数を数える。バイナリ (`-` `-`、または先頭 8KB に NUL) は行数なし
- 並び順はツリー順。名前の変更は新しいパスで並べる
- 各ファイルに `version` を付ける。状態・元のパス・基準の blob・行数・今の内容のハッシュから作る文字列で、変更が変わると変わる (Viewed の判定に使う)。基準の側だけが変わったとき (コミットのやり直し、`git fetch` で分岐点が動いたなど) も変わる

## 1 ファイルの差分

`GET /api/diff?path=` (ブランチと比べるときは `&base=`) は、その基準の一覧に今あるパスだけを受け付ける (無ければ `404`)。

- 最初に基準のコミット (`rev-parse HEAD` か `merge-base <refname> HEAD`) を決め、変更前の内容と行の差分の両方にそのコミットを使う (途中でコミットされても、両方が同じコミットを指すように)
- 変更前の内容: `cat-file blob <コミット>:./<元のパス>` (追加なら空)
- 変更後の内容: 作業ツリーのファイル (削除なら空)。シンボリックリンクはリンク先のパス
- どちらかがバイナリ (先頭 8KB に NUL) か画像なら `kind: "binary"` を返す。画面には `Binary file not shown.` と出す
- 行の差分 (変更のまとまり): 追跡済みで変更・名前の変更なら `diff-index <コミット> -M --relative -p -U0 --no-color --no-ext-diff --no-textconv -- :(literal)<元のパス> :(literal)<パス>` の hunk のヘッダーを読む。追加は全行の追加、削除は全行の削除とする
  - パスには `:(literal)` を付ける (`a*.txt` のようなファイル名を、ワイルドカードとして他のファイルに当てないため)
  - hunk のヘッダーの `@@` の後ろの関数名も受け取り、そのまとまりの見出しに使う
  - Git は作業ツリーを読み直し、インデックスにあるものと比べる。そのため hunk の削除行・追加行が、読んだ変更前・変更後の行と一致するか確かめる。一致しなければ (途中でファイルが書き換わった、`git rm --cached` でインデックスに無い など)、読んだ行どうしを自前の Myers で比べる (関数名は無し)
- 変更前・変更後の行を、それぞれファイル全体で Shiki でハイライトする (`viewer.max_highlight_bytes` を超える側はハイライトしない)。前後の行の展開に使うため、全行を返す
- 単語の強調: 1 つのまとまりの中で、i 番目の削除行と i 番目の追加行を組にし、トークン (英数字と `_` の並び / 空白の並び / それ以外の 1 文字) の列を Myers で比べる。違うトークンの範囲を `<span class="diff-word">` で囲む。共通の空白でないトークンが 1 つも無い組は強調しない (全部が強調になって読みにくいため)
- Markdown は、上に加えてレンダリングした差分 (`richHtml`) も返す ([レンダリングした差分](#レンダリングした差分))。`viewer.max_highlight_bytes` を超えるときは返さない

## 差分の表示

### 行

- 1 行ずつ、変更前の行番号・変更後の行番号・`+` / `-` / 空白・内容を出す。削除行は変更前の行番号だけ、追加行は変更後の行番号だけを出す
- 変更のまとまりの前後に、変わっていない行を 3 行ずつ出す。間が 6 行以下なら、2 つのまとまりを 1 つの hunk にまとめる
- 各 hunk の先頭に `@@ -<旧の開始>,<行数> +<新の開始>,<行数> @@ <関数名>` を出す
- 隠れている変わらない行は、hunk のヘッダーの行のボタンで展開する。隠れているのが 20 行以下なら全部を 1 回で、それより多ければ 20 行ずつ出す。ファイルの末尾の隠れた行も同じく展開できる

### ファイルのカード

- ヘッダー: 開閉のボタン、パス (名前の変更は `<元のパス> → <パス>`)、状態のラベル (`Added` / `Deleted` / `Renamed`)、`+<追加> −<削除>`、Markdown なら表示の切り替え、`Viewed` のチェックボックス
- ヘッダーのクリックで開閉する。Viewed を付けたら閉じる
- 追加と削除の行数の合計が 500 を超えるファイルは、最初は閉じておき、`Load diff` のボタンで開く (ページが重くならないように)
- 差分は、カードを開いたときに取る。`version` が変わったら取り直す

### Viewed

- `Viewed` のチェックは、`localStorage` の `reviewbuddy.viewed.<セッション ID>` (ブランチと比べるときは `reviewbuddy.viewed.<セッション ID>.<ブランチ>`) に `{ <パス>: <version> }` として保存する。ブラウザごとの設定で、サーバーには送らない。基準ごとに分けるのは、基準が違えば一覧も `version` も違い、書くときに一覧に無いパスを消すと他の基準の印まで消えるため
- 保存した `version` が今の `version` と同じときだけ Viewed とする。Viewed の後でファイルが変わると外れる (Agent の追加の修正を見落とさないため)
- 書くときに、今の一覧に無いパスは消す
- Changes 画面の上部に `<Viewed の数> / <ファイル数> viewed` を出す

### コメント

- 各カードの右に Comment Pane を置く。規則は Viewer と同じ ([画面構成.md](./画面構成.md))。開閉の状態も共通 (`reviewbuddy.commentPane`)
- 変更後の行番号のある行 (追加された行と、変わっていない行) の行番号をクリックして選ぶ。Shift+クリック・ドラッグで範囲を広げる。範囲は変更後の行番号で表し、間の削除行は範囲に影響しない
- 削除行には行番号のクリックを付けない
- 作るスレッドは普通のスレッド (`originView: "source"`)。通常のファイル表示にも出る
- 差分に出すスレッドは、範囲のどこかの行が今見えているもの。カードは範囲の中で最初に見えている行の高さに揃える
- 削除されたファイルにはコメントできない (Comment Pane も出さない)
- コミットしても、スレッドは自動では Outdated にしない。要らなくなったら参加者が Resolve する

## レンダリングした差分

Markdown のカードの既定の表示。カードのヘッダーで Source の差分と切り替える。GitHub の rich diff と同じく、hunk には区切らず文書全体を出す。

### ブロックの突き合わせ

1. 変更前と変更後を markdown-it でそれぞれ解析し、最上位のブロック (段落・見出し・リスト・表・コードブロック・引用・水平線・HTML ブロック) に分ける
2. 各ブロックの元のテキスト (末尾の空行を除く) を比べるキーにして、ブロックの列を Myers で比べる
3. 同じブロックはそのまま出す。違うところは、削除されたブロックと追加されたブロックを前から順に組にする

| 組 | 出し方 |
|----|--------|
| 同じ種類の段落・見出し (同じレベル)・引用 | 1 つのブロックとして出し、中の単語の違いを `<del>` / `<ins>` で示す。左端に黄色の線 |
| 同じ種類のリスト (箇条書き / 番号付き) | リストの項目の列を同じ方法で比べる。項目ごとに、同じ / 追加 / 削除 / 単語の違い で出す。リストの左端に黄色の線 |
| 上記以外 (表・コードブロック・Mermaid の図・種類の違うブロック) | 削除されたブロックと追加されたブロックを上下に並べる |
| 組にならないブロック | 削除は赤の背景と取り消し線、追加は緑の背景。表・コードブロック・図は左端に赤 / 緑の線 |

- ブロックの中の単語の比較は、レンダリングした HTML をタグ / 文字参照 / 英数字の並び / 空白の並び / それ以外の 1 文字 に分けて Myers で比べる。変更後のタグはすべて残し、削除されたタグは捨てる (HTML の構造を壊さないため)。削除された文字は `<del>`、追加された文字は `<ins>` で囲む
- 変更前の側のブロックからは `data-src-start` / `data-src-end` を外す。変更後のブロックにだけ残し、Preview と同じ仕組みでコメントの対象にする

### コメント

- 今の Preview と同じく、ブロックにホバーすると出る「+」から付ける (`originView: "preview"`)
- 「+」は変更後の行に対応するブロック (追加・変わっていない・単語の違い) にだけ出る。削除されたブロックと、変更前の表・図には出ない

## ライブ更新

- 監視でまとまった変更 (ファイルの変更・追加・削除、`.git/` の中の変化) のたびに、サーバーは変更の一覧のキャッシュを捨て、`changes.changed` を配信する ([API.md](./API.md))。コミットは `.git/` の中の変化として届く
- ルートがリンクされた worktree か、リポジトリの中のディレクトリのときは、Git のディレクトリがルートの外にあり、コミットしてもルートの中は何も変わらない。そのため `rev-parse --path-format=absolute --git-dir --git-common-dir` で求めたルートの外のディレクトリ (HEAD・インデックス・packed-refs) と、その `refs/` (ブランチ) も監視する (Git 2.31 以降)
- ブラウザは `changes.changed` で、今の基準の `GET /api/changes` と `GET /api/branches` を取り直す。`version` が変わったカードは差分を取り直す。`git fetch` でリモート追跡ブランチが動いたときも `.git/` の中の変化として届く
- 同時に多くのブラウザが取り直してもいいように、サーバーは一覧を基準ごとに 1 回だけ計算して共有する。監視をしない (`--no-watch`) ときはキャッシュしない
- 基準を切り替えたら、その基準の一覧が届くまでカードを出さない (前の基準の一覧で差分を取りに行かないため)

## テスト観点

- 一覧: 変更・追加 (ステージ済み / 未追跡)・削除・名前の変更 (`git mv`)・`touch` だけのファイル (出ない)・`.gitignore` の対象 (出ない)・バイナリ (行数なし)・ルートがサブディレクトリ・HEAD が無い・Git 管理外 (`git: false`)・ルートの外を指すシンボリックリンク (リンク先を読まない)・`git rm --cached` (1 つの modified、同じなら出ない)・HEAD の側だけの変化で `version` が変わる
- 1 ファイルの差分: シンボリックリンク (リンク先のパスどうし)、Git の hunk が読んだ行と合わないとき (自前の比較)、ワイルドカードの文字を含むファイル名
- ライブ更新: リンクされた worktree と、リポジトリの中のディレクトリをルートにしたときのコミット
- 一覧と差分を取っても `.git/index` の mtime が変わらない
- 比較の基準: ブランチの一覧 (今のブランチと `origin/HEAD` を除く、Local / Remote)、ブランチでコミットした変更と未コミットの変更が両方出る、分岐後にブランチ側だけに入った変更は出ない、一覧に無い名前 (`--output=x`・`HEAD~1` を含む) は `404`、共通の祖先が無いと `400`、`branches` と `merge-base` で `.git/index` の mtime が変わらない
- hunk のヘッダーの読み取り: 行数の省略、行数 0、関数名
- 単語の強調: 一部だけ違う組、空白だけ違う組、共通のトークンが無い組 (強調しない)、HTML の特殊文字を含む行
- 行の組み立て: 前後 3 行、間が 6 行以下でまとまる、展開 (20 行ずつ / 全部)、ファイルの先頭と末尾
- レンダリングした差分: 段落の追加 / 削除 / 単語の違い、リストの項目の追加 / 削除 / 変更、表の変更 (上下に並ぶ)、変更前の側に `data-src-*` が無い
- Viewed: 保存と読み出し、`version` が変わると外れる、不正な値は無視する
- E2E: Changes 画面の切り替え、カードとツリー、Viewed で閉じて再読み込み後も保つ、追加行へのコメント (変更後の行番号で保存される)、レンダリングした差分の `<ins>` / `<del>` と「+」、ファイルを書き換えると差分が更新される、ブランチを選ぶとコミットした変更も出て URL に残り (再読み込み・`Files` との行き来の後も)、`HEAD` に戻せる

***

## 未決事項

- 画像の差分 (変更前と変更後を並べる) は出さない。必要になったら追加する
- 一覧と差分の計算が重いリポジトリ (変更が数千ファイル) での振る舞いは、使ってみて必要なら絞り込みを入れる。長く分かれたブランチと比べると起きやすい
- ブランチが多いリポジトリでの `Compare with` の絞り込み (検索) は、使ってみて必要なら入れる
