# リリース手順

**目的: akapen の新しい版を GitHub Releases に出し、mise で入れられることを確かめるまでの手順を定める。**

- 設計: [配布.md](../design/配布.md) / [ADR-0005](../adr/0005-distribution-mise-github.md)
- ワークフロー: `.github/workflows/release.yml` (タグ `v*` の push で動く)

***

## 前提

- `main` の CI (`.github/workflows/ci.yml`) が macOS と Linux で通っている
- 手元に `gh` (認証済み) と `mise` がある
- リポジトリが private の間は、mise がリポジトリを読めるトークンを使える (`gh auth login` 済みか、`MISE_GITHUB_TOKEN`)。`mise token github` で確かめる

***

## 手順

1. `package.json` の `version` を新しい版にする (例: `0.2.0`)。semver に従う

   ```sh
   git switch main && git pull
   # package.json の "version" を編集する
   bun run verify
   git commit -am "chore: release 0.2.0"
   git push origin main
   ```

2. タグを付けて push する。タグは `v` + `package.json` の版にする (違うとワークフローの最初のステップで失敗する)

   ```sh
   git tag v0.2.0
   git push origin v0.2.0
   ```

3. ワークフローの完了を待つ

   ```sh
   gh run watch "$(gh run list --workflow release.yml --limit 1 --json databaseId --jq '.[0].databaseId')"
   ```

   ワークフローは、3 つのターゲット (`linux-x64` / `linux-arm64` / `darwin-arm64`) のビルド → macOS 版の ad-hoc 署名 → `akapen-v<版>-<os>-<arch>.tar.gz` と `checksums.txt` の作成 → GitHub Release の作成 → macOS と Linux での `mise exec` によるスモークテスト、の順に動く

***

## 検証

```sh
gh release view v0.2.0                       # 3 つのアーカイブと checksums.txt があること
mise exec github:dannygim/akapen@0.2.0 -- akapen --version   # 0.2.0 が出ること
xattr -l "$(mise where github:dannygim/akapen@0.2.0)/akapen" # com.apple.quarantine が無いこと
```

`mise use -g github:dannygim/akapen` で入れている人は、`mise upgrade` で新しい版になる。

***

## ロールバック

- 壊れた版を出してしまった場合は、Release とタグを消す。利用者は前の版を指定して入れ直す

  ```sh
  gh release delete v0.2.0 --yes --cleanup-tag
  mise use -g github:dannygim/akapen@0.1.0
  ```

- ワークフローの途中で失敗した場合 (Release が作られていない) は、原因を直して main に push し、タグを付け直す

  ```sh
  git tag -d v0.2.0 && git push origin :refs/tags/v0.2.0
  # 修正を push してから手順 2 からやり直す
  ```

***

## 既知の問題

- **クロスコンパイルの対象の Bun のダウンロードの失敗**: `bun scripts/build.ts --target ...` は対象の Bun をダウンロードする。一時的な失敗ならジョブを再実行する
- **artifact attestation と packslip は付けていない**: private リポジトリでは artifact attestation に GitHub Enterprise Cloud が必要なため。public にしたら `actions/attest-build-provenance` と `jdx/packslip@v1` を足す ([配布.md](../design/配布.md))
- **macOS 版は ad-hoc 署名**: Developer ID で署名・公証していない。mise はダウンロードしたファイルに quarantine 属性を付けないため、Gatekeeper の警告は出ない見込み。ブラウザでダウンロードした場合は `xattr -d com.apple.quarantine akapen` で外す
