# レンダリング調査 (Markdown / コードハイライト / Mermaid)

**目的: Markdown の Preview、コードのハイライト、Mermaid の図の描画に使うライブラリを比較し、行範囲の取り方などの実測結果を確認日付きで記録する。**

***

## 前提

- 調査日: 2026-10-23
- 凡例: **確認済** = 公式ドキュメントか、手元で実行して確認したもの / **要検証** = 二次ソースや推測
- 検証環境: Linux コンテナ上の Bun 1.4.4 / markdown-it 15.0.3 / Shiki 4.5.0
- 前提となる要件: Preview 表示のまま、元ファイルの行範囲にひも付くコメントを付けたい ([要件.md](../design/要件.md) の F6 / F9)

***

## 仕様サマリー

### Markdown パーサーの比較

| | Bun.markdown | markdown-it 15 | remark (unified) | marked |
|---|---|---|---|---|
| ソース位置 | なし | ブロックトークンに `map: [開始, 終了)` | 全ノードに `position` (行・列・offset) | 行番号なし (`raw` から自前で数える) |
| GFM | 表・取り消し線・タスク・autolink | 表・取り消し線は内蔵、`linkify` はオプション、タスクリストはプラグイン | `remark-gfm` | 内蔵 |
| HTML 出力 | 直接 | 直接 (レンダラーの差し替えが容易) | mdast → hast → HTML の多段 | 直接 |
| 依存 | なし (組み込み) | 小 | 多 | 小 |
| 所感 | 速いが位置情報がない | **行範囲の付与が最も簡単** | 柔軟だが重い | 位置情報が弱い |

Bun.markdown と markdown-it の列は手元で確認済み ([Bun_調査.md](./Bun_調査.md))。remark と marked の列は一般知識に基づくもので **要検証**。VS Code の Markdown Preview も markdown-it の行情報 (`data-line` 属性) でエディタとのスクロールを同期している **要検証**。

### markdown-it の `map` の実測 (15.0.3)

入力 (左端の数字は 0 始まりの行番号):

```text
0  # Title
1
2  Paragraph line 1
3  line 2
4
5  - item a
6  - item b
7    - nested
8
9  | a | b |
10 |---|---|
11 | 1 | 2 |
12 | 3 | 4 |
13
14 ```mermaid
15 graph LR
16   A-->B
17 ```
18
19 > quote
```

結果:

| トークン | `map` | 備考 |
|---------|-------|------|
| `heading_open` | `[0,1]` | |
| `paragraph_open` | `[2,4]` | 複数行の段落 |
| `bullet_list_open` | `[5,9]` | 後続の空行 (8 行目) まで含む |
| `list_item_open` (item a) | `[5,6]` | |
| `list_item_open` (item b) | `[6,9]` | ネストした子を含み、空行まで含む |
| `list_item_open` (nested) | `[7,9]` | |
| `table_open` | `[9,13]` | |
| `tr_open` (ヘッダー) | `[9,10]` | 区切り行 (10 行目) はどの `tr` にも属さない |
| `tr_open` (データ行) | `[11,12]` / `[12,13]` | 行ごとにコメントできる |

### Shiki

- 最新は 4.5.0。v4 の破壊的変更は Node.js 18 のサポート終了と、typo だった非推奨 API の削除程度 **確認済**
- Bun 1.4.4 上で `codeToHtml(code, { lang, themes: { light: "github-light", dark: "github-dark" } })` が動作する。出力は 1 行ごとに `<span class="line">` になり、行番号の付与や行選択に使える **確認済** (実行)
- デュアルテーマは CSS 変数 (`--shiki-dark`) で切り替える **確認済** (出力で確認)
- ファイル名から言語への対応 (`Dockerfile`、`mise.toml`、`.env` など) は自前の対応表を持ち、不明なものは `text` にする **要検証**
- 全言語・テーマを含めるとバイナリが約 114MB になる。`shiki/core` + 使う言語だけにすると縮むはず **要検証** ([Bun_調査.md](./Bun_調査.md))

### Mermaid

- 最新は 12.2.0 (メジャー v12)。GitLab の移行 MR に「既定値が変わった設定があるため、図の比率が変わらないよう調整した」とある → v12 の変更点は実装時に確認する **要検証**
- DOM が必要なため、クライアント側で描画する。`securityLevel: 'strict'` が v12 でも同じ意味で使えるか **要検証**

## 重要な気づき

- **markdown-it の `map` は 0 始まりで、終了行を含まない**。画面やプロンプトで使う 1 始まり・両端を含む範囲は `start + 1 .. end` で求める
- **リスト系は後続の空行まで範囲に含む**ため、末尾の空行を除いて扱う必要がある
- **ネストしたリスト項目は親の範囲に子が含まれる**。クライアントは最も内側の要素を採用する
- **表の区切り行はどの行にも属さない**。ヘッダー行とデータ行には個別にコメントできる
- **Mermaid とサニタイズの詳細 (v12 の既定値、`securityLevel`) は未検証**。M2 で組み込む前に確認する
