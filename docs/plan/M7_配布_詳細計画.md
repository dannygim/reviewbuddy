## 目的

- 配布の非機能要件 ([要件.md](../design/要件.md)) と、全体計画の完了条件 5・6 (mise で入ること、README)
- CI (`bun run verify` を macOS / Linux で実行) は D の直後に前倒しで入れ済み

## スコープ

- リリースのワークフロー (`.github/workflows/release.yml`、タグ `v*`): タグと `package.json` の版の一致確認 → `linux-x64` / `linux-arm64` (Linux のランナーでクロスコンパイル) と `darwin-arm64` (macOS のランナーでビルドし、entitlements 付きで ad-hoc 署名) → `akapen-v<version>-<os>-<arch>.tar.gz` と `checksums.txt` → GitHub Release → `mise` で入れて `akapen --version` を確かめるスモークテスト
- README (使い方、mise での入れ方と private リポジトリのトークン、設定ファイル、`tailscale serve` での共有、開発のコマンド)
- リリース手順の Runbook (`docs/ops/`)
- v0.1.0 のリリースと、手元の Mac での確認 (mise の自動判定、quarantine 属性の有無)

## 非スコープ

- artifact attestation と packslip (public にした後。private の間は GitHub Enterprise Cloud が要るため付けられない)
- Developer ID による署名と公証 (ブラウザ経由で配らないため不要の見込み)
- `darwin-x64` (主対象は Apple silicon。要望があれば足す)

## タスク分解

### Task 1: リリースのワークフロー

- **Files**: `.github/workflows/release.yml` / `packaging/entitlements.plist` / `scripts/package.ts` (アーカイブと checksum の作成)
- ビルドのフラグは `bun run build` と同じ (`--splitting --minify --sourcemap --no-compile-autoload-dotenv --no-compile-autoload-bunfig`) に `--target` を足す
- macOS: `codesign --force --sign - --entitlements packaging/entitlements.plist dist/akapen` → `codesign --verify`
- スモークテストは同じリポジトリの Release を読むので、`MISE_GITHUB_TOKEN` にワークフローの `GITHUB_TOKEN` を渡す

### Task 2: README と Runbook

- **Files**: `README.md` / `docs/ops/リリース手順.md`
- README は英語 (UI が英語のため)。設計の詳細は `docs/` (日本語) へリンクする

### Task 3: v0.1.0 のリリース

- `package.json` の `version` を `0.1.0` にして commit → タグ `v0.1.0` を push → ワークフローの成功を確認 → 手元で `mise exec` と `xattr` を確認 → 結果を本計画に追記する

## リスク

| # | リスク | 対応 |
|---|--------|------|
| R1 | mise のアセットの自動判定が意図と違うものを選ぶ | ファイル名に OS / arch を含め、`akapen-` で始める。だめなら利用側の設定に `asset_pattern` を書く |
| R2 | クロスコンパイルの対象の Bun のダウンロードに失敗する | ジョブを再実行する。続くなら各 OS のランナーでビルドする |
| R3 | ad-hoc 署名では Gatekeeper の警告が出る | mise は HTTP でダウンロードするため quarantine 属性が付かない見込み。付いていたら README に `xattr -d com.apple.quarantine` を書く |

## 結果 (2026-10-23)

- タグ `v0.1.0` で、`akapen-v0.1.0-darwin-arm64.tar.gz` (47.9MB) / `-linux-arm64.tar.gz` (59.2MB) / `-linux-x64.tar.gz` (59.3MB) と `checksums.txt` が Release に載った
- 最初のスモークテストは失敗した。mise がアセットの GitHub artifact attestation を API で確かめようとし、ワークフローのトークンに `attestations: read` が無く 403 になったため。スモークテストを再利用できるワークフロー (`.github/workflows/smoke.yml`) に分けて権限を付け、手動で実行したところ macOS (`darwin-arm64` を選択) と Linux (`linux-x64` を選択) の両方で `0.1.0` が出た ([実行](https://github.com/dannygim/akapen/actions/runs/39918098210))
- 手元の Mac (macOS、Apple silicon) で `mise exec github:dannygim/akapen@0.1.0 -- akapen --version` が `0.1.0` を出した。入ったバイナリに `com.apple.quarantine` は無く、ad-hoc 署名は `codesign --verify` を通る
- README の誤りを直した: `gh auth login` だけでは mise は gh のトークンを使えない (macOS では gh がキーチェーンに保存するため)。`github.credential_command` の設定を案内する
