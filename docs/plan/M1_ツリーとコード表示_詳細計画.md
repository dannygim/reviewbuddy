# M1 ツリーとコード表示 詳細計画

**目的: File Tree にルートのファイルを Git と同じ基準で出し、選んだファイルを GitHub 風のハイライト付きで表示できるようにする。**

- 上位計画: [akapen_実装計画.md](./akapen_実装計画.md) の M1
- 設計: [ファイル一覧と表示.md](../design/ファイル一覧と表示.md) / [セキュリティ.md](../design/セキュリティ.md) / [API.md](../design/API.md) / [画面構成.md](../design/画面構成.md)
- 作成日: 2026-10-23
- 書き方: M0 と違い、本計画はコードの全文を載せない (計画を書いてすぐ同じセッションで実装するため)。各タスクはファイル・関数の形・テストケース・確認方法までを定める

## 目的

- 対象の要件: F4 (File Tree) / F5 (ファイルの表示、URL ハッシュ) / F8 (コードハイライト)、バイナリ・巨大ファイルの表示
- セキュリティ: ファイルを配信し始めるため、パスの検証と `Host` ヘッダーの許可リストもこのフェーズで入れる

## スコープ

- FileIndex (Git / Git 管理外 / 常に除外するもの)、ツリー順、ツリーの組み立て
- `GET /api/tree` / `GET /api/file?path=` / `GET /api/raw?path=`
- ファイルの種類の判定 (`markdown` / `code` / `large` / `image` / `binary`)、Shiki によるハイライト (言語を絞る)、キャッシュ
- パスの検証、`Host` ヘッダーの許可リスト、`/api/raw` の CSP
- SPA: ヘッダー・File Tree・Viewer のレイアウト、ハッシュルーティング (`#/doc/<path>`)、行番号付きのコード表示、画像・バイナリの表示
- `Bun.WebView` による E2E テストの土台

## 非スコープ

- Markdown の Preview (M1 では Markdown もハイライト付きのソースとして出す) → M2
- 未解決スレッドの数のバッジ、行の選択 → M3
- プレゼンス → M4
- ファイルの監視 (`file.changed` / `tree.changed`)、`viewer.exclude` と `max_highlight_bytes` の設定ファイルからの読み込み → M6 (M1 では既定値を引数で渡せるようにだけしておく)

## タスク分解

### Task 1: ツリー順とツリーの組み立て

- **Files**: `src/shared/tree.ts` / `src/shared/tree.test.ts`
- **Produces**:
  - `compareTreePaths(a: string, b: string): number` — セグメントごとに比べ、同じ階層ではディレクトリを先にする。名前は大文字・小文字を区別せずに比べ、同じなら区別して比べる
  - `type TreeNode = { name: string; path: string; children?: TreeNode[] }` (`children` があればディレクトリ)
  - `buildTree(paths: string[]): TreeNode[]` — ルート直下のノードの配列をツリー順で返す
- **テストケース**: `["b/x.md", "A.md", "a.md", "c/d.md", "B.md", "b/a/z.ts"]` の並び / ディレクトリが先 / 大文字・小文字だけ違う名前の順 / `buildTree` の入れ子と順序

### Task 2: FileIndex

- **Files**: `src/files/file-index.ts` / `src/files/file-index.test.ts`。依存に `ignore@7.0.13` を足す
- **Produces**:
  - `listFiles(root: string, options?: { exclude?: string[] }): Promise<string[]>` — ツリー順に並べた相対パス
  - `class FileIndex` — `static create(root, options)`、`paths(): string[]`、`has(path): boolean`、`refresh(): Promise<boolean>` (変わったら `true`)
- **実装の要点**: `git -C <root> rev-parse --is-inside-work-tree` が成功すれば `git ls-files --cached --others --exclude-standard -z`、失敗 (Git 管理外・`git` が無い) なら `ignore` で各階層の `.gitignore` を積み上げて走査する。どちらも `.git/` と `exclude` のパターンを除き、存在しないファイル・ディレクトリ (gitlink) を除く
- **テストケース** (一時ディレクトリにリポジトリを作る): 調査の 7 ケース (ルートの `.gitignore`、`git add -f`、サブディレクトリの `.gitignore`、`.git/info/exclude`、未追跡、削除済み、サブディレクトリをルートにする) / Git 管理外でネストした `.gitignore` / `exclude` / `refresh()` の戻り値

### Task 3: パスの検証と Host の許可リスト

- **Files**: `src/files/resolve.ts` / `src/files/resolve.test.ts` / `src/security.ts` / `src/security.test.ts`
- **Produces**:
  - `resolveFile(root: string, index: FileIndex, path: string): string | null` — 一覧に含まれ、realpath がルートの中のときだけ絶対パスを返す
  - `isAllowedHost(host: string | null, allowedHosts: string[]): boolean` — IP リテラル (`[::1]` を含む) / `localhost` / `*.ts.net` / `allowedHosts` を許す。ポートは無視する
- **テストケース**: 一覧に無いパス / `../` / ルートの外を指すシンボリックリンク (一覧に入っていても拒否) / 正常なパス。Host は `127.0.0.1:4400` / `localhost` / `[::1]:4400` / `100.64.0.1` / `mac.tail1234.ts.net` / `evil.example` / `null` / `allowedHosts` に入れた名前

### Task 4: ファイルの種類の判定とハイライト

- **Files**: `src/render/language.ts` / `src/render/highlight.ts` / `src/render/file-view.ts` と各テスト。依存に `shiki@4.5.0` を足す
- **Produces**:
  - `detectLanguage(path: string): string` — ファイル名の完全一致 → 拡張子 → `text`
  - `highlightLines(code: string, lang: string): Promise<string[]>` — 行ごとの HTML (`<span style="color:…;--shiki-dark:…">…</span>`)。`shiki/core` + Oniguruma エンジン + 対応表の言語だけを読み込む
  - `renderFile(absPath: string, path: string, options: { maxHighlightBytes: number }): Promise<FileView>` — 種類を判定して `FileView` を返す。`(path, mtimeMs, size)` をキーに最大 200 件をキャッシュする
  - `FileView` 型 (`src/shared/api.ts`): `kind` / `path` / `mtime` と、テキスト系 (`markdown` / `code` / `large`) は `lang` / `lines` (元の行) / `lineHtml` (行ごとの HTML)
- **テストケース**: 言語 (`Dockerfile` / `Makefile` / `mise.toml` / `.env.local` / `a.ts` / `x.unknown`) / 種類 (`.png` / NUL を含む / 閾値ちょうど・超え / `.md`) / HTML のエスケープ (`<b>` がタグにならない) / 空ファイル・末尾の改行 / キャッシュが mtime の変化で効かなくなる

### Task 5: API とサーバーの組み立て

- **Files**: `src/server.ts` / `src/server.test.ts` / `src/cli.ts`
- **Produces**: `startServer(options)` の `options` に `index: FileIndex` / `allowedHosts: string[]` / `maxHighlightBytes: number` を足す。`GET /api/tree` / `GET /api/file?path=` / `GET /api/raw?path=` を足し、`/api/*` すべてに Host の検証をかける
- **実装の要点**: `cli.ts` は FileIndex の作成で非同期になる。`--bytecode` の出力が CommonJS のため、トップレベル await は使わず `run(argv).catch(...)` にする
- **テストケース**: `/api/tree` の順序 / `/api/file` の `code` と `binary` / `/api/raw` の Content-Type・CSP・`nosniff` / 一覧に無いパスが `404` / `Host: evil.example` が `403` / 既存の M0 のテスト

### Task 6: SPA (File Tree と Viewer)

- **Files**: `src/web/App.tsx` / `src/web/api.ts` / `src/web/router.ts` / `src/web/FileTree.tsx` / `src/web/Viewer.tsx` / `src/web/styles.css` / `test/e2e/viewer.test.ts`
- **画面**: ヘッダー (アプリ名・ルート)、左に File Tree (ディレクトリの折りたたみ。選んだファイルの祖先は自動で開く)、右に Viewer (行番号のガター + 行ごとの HTML、画像、"Binary file not shown")。ハッシュ `#/doc/<path>` と選択を同期する
- **E2E** (`Bun.WebView`): 一時ディレクトリのリポジトリでサーバーを起動 → ツリーのファイルをクリック → コードの行が出て、ハッシュが変わる / ハッシュ付きの URL を直接開く

### Task 7: 計測

- **Files**: `scripts/perf-tree.ts` (計測用。CI では動かさない)
- 2 万ファイル (深さ 3 程度のディレクトリに分散) の一時リポジトリで、`FileIndex.create` と `/api/tree` の応答の時間を測る
- `bun run build` のバイナリのサイズを測る
- 結果を本計画の「計測結果」に追記する

## リスク

| # | リスク | 対応 |
|---|--------|------|
| R1 | `Bun.WebView` は実験的な API。Linux の CI では Chrome が要る | GitHub の `ubuntu-latest` には Chrome が入っている。不安定なら E2E を macOS だけで動かす |
| R2 | `git` が無い環境 | `rev-parse` の失敗で Git 管理外として扱う (`ignore` による判定) |
| R3 | 大きなファイルのハイライトで応答が遅れる | `max_highlight_bytes` を超えたらハイライトしない。キャッシュする |
| R4 | Shiki の言語を絞ったことで、ハイライトされない言語がある | 対応表に無い言語は `text`。要望が出たら足す (1 言語あたりのサイズは小さい) |

## 計測結果

2026-10-23、macOS (Apple silicon)、Bun 1.4.4 で `bun scripts/perf-tree.ts` を 3 回実行した (2 万ファイル、Git リポジトリ)。

| 項目 | 結果 |
|------|------|
| `FileIndex.create` | 109〜174 ms |
| `GET /api/tree` | 2〜7 ms (479 KB) |
| ページの読み込みからツリーの描画まで (`Bun.WebView`) | 462〜681 ms |

合わせて 1 秒以内に収まり、完了条件を満たす。`@tanstack/react-virtual` は入れない (ツリーは閉じた状態で始まり、開いた階層だけを描画するため)。

バイナリのサイズ (`bun run build`、macOS arm64):

| ビルドのフラグ | サイズ | 起動 (URL を出すまで、中央値) |
|---------------|--------|------------------------------|
| `--minify` | 98.5 MB | — |
| `--minify --sourcemap` | 101.0 MB | 34〜36 ms |
| `--minify --sourcemap --bytecode` | 112.4 MB | 22 ms |

**`--bytecode` は外した。** 起動が約 13ms 速くなるだけで、サイズが約 11MB 増えるため。akapen は一度起動すればサーバーとして動き続けるので、起動の速さよりも配布のサイズを優先する。外したことで、CommonJS 出力の制約 (トップレベル await が使えない) もなくなる。`--sourcemap` はスタックトレースが元のソースを指すため残す。

Shiki の言語を絞った効果: 全言語を含む試作は約 114MB (Linux x64)、絞った M1 のバイナリは 101MB。
