## 目的

- 起動した本人が、`.gitignore` で除外したローカルのメモや生成物も reviewbuddy で読み、コメントできるようにする
- 参加者には、ignored ファイルの一覧も中身も返さない
- プロンプトを Coding Agent に渡す操作 (`Copy prompt`) を、起動した本人に限る

## スコープ

- Owner の判定: 接続元が loopback・`Host` が同じマシン・`X-Forwarded-For` / `X-Forwarded-Host` / `Forwarded` なし。`GET /api/session` の `owner`、WebSocket の Owner 向けのトピック
- ignored ファイルの一覧: `git ls-files --others --ignored --exclude-standard --directory --no-empty-directory` (Git 管理外は走査)。畳んだディレクトリは開いたときに 1 階層ずつ読む
- `GET /api/tree/ignored` (Owner のみ)、`GET /api/file` / `GET /api/raw` で Owner に ignored ファイルを返す
- ignored ファイルのスレッド: Owner だけが書き込める。参加者にも見える (`ignored` を付けて送る)。再アンカーと `file.changed` (Owner にだけ) に対応する
- `POST /api/prompt` を Owner に限る。参加者の画面には "Copy prompt"・"Resolve copied threads"・チェックボックスを出さない
- 画面: ヘッダーの目の形のボタン (Owner・Files の画面のみ、`localStorage` に保存)、File Tree での ignored の項目の表示と遅延読み込み、ignored ファイルを開いている間のプレゼンス、参加者の閲覧だけの表示
- ドキュメント (README を含む) と v0.8.0 のリリース

## 非スコープ

- Changes 画面に ignored ファイルを出すこと (Git の変更にならないため)
- ignored ファイルの追加・削除のライブ反映 (`tree.changed` を受けたときと出し直したときに取り直す)
- 参加者への ignored ファイルの公開、Owner を複数にすること、Owner を画面から譲ること
- Owner の PIN の省略 (Owner も今までどおり PIN を入力する)
- End など、ほかの操作の権限の変更
- Tailscale の ID ヘッダーによる本人の確認 (v2 候補)

## 完了条件

- [ ] `bun run verify` が通り、CI (macOS / Linux) も通る
- [ ] 単体テスト: Owner の判定、ignored ファイルの一覧 (Git / Git 管理外)、畳んだディレクトリの読み込み、ignored ファイルの判定、ツリーへの混ぜ込み、`localStorage` の値の読み取り
- [ ] サーバーのテスト: 参加者 (`X-Forwarded-For` 付き) は `GET /api/tree/ignored` と `POST /api/prompt` が `403`、ignored ファイルの `GET /api/file` / `GET /api/raw` が `404`、ignored ファイルのスレッドへの書き込みが `403`。Owner ではすべて通る。`GET /api/session` の `owner`。ignored ファイルの `file.changed` が参加者に届かない。ignored ファイルのスレッドが起動のたびに Outdated にならない

## 全体の制約

- 依存を増やさない (ADR-0001)
- git は `git --no-optional-locks -C <root>` で使い、`.git/index` に書き込まない
- 対象ディレクトリに書き込まない。表示・非表示はブラウザの `localStorage` だけに保存する
- 権限はすべてサーバーで確かめる。画面の出し分けは表示のためだけ
- UI の文言は英語

## タスク分解

Task 1〜5 はサーバー、Task 6〜7 はクライアント。各タスクはテストを先に書く。

### Task 1: Owner の判定

- `isOwnerRequest(address: string | null, headers: Headers): boolean` を `src/security.ts` に足す ([セキュリティ.md](../design/セキュリティ.md#owner) の 3 条件)
- テスト: 接続元 `127.0.0.1` / `127.255.0.1` / `::1` / `::ffff:127.0.0.1` / `100.64.0.1` / `192.168.0.2` / `null`、`Host` の `127.0.0.1:4400` / `localhost` / `LOCALHOST:4400` / `[::1]:4400` / `0.0.0.0:4400` / `[::]:4400` / `mac.tail1234.ts.net` / 無し、`X-Forwarded-For` / `X-Forwarded-Host` / `Forwarded` のどれか 1 つがあれば偽

### Task 2: サーバーに Owner を通す

- `ServerOptions.isOwner?: (req: Request) => boolean` を足す。省略時は `isOwnerRequest(server.requestIP(req)?.address, req.headers)`。E2E で参加者を再現するために差し替えられるようにする
- `SessionInfo.owner` を `GET /api/session` で返す
- WebSocket: upgrade で判定した結果を `SocketData.owner` に入れ、Owner なら `owner` のトピックも購読する。`Hub.publishToOwner(event)` を足す
- テスト: `127.0.0.1` からの `fetch` で `owner: true`、`X-Forwarded-For` を付けると `false`。Owner 向けのイベントが参加者の WebSocket に届かない

### Task 3: ignored ファイルの一覧と判定

- `listIgnored(root, options)`: Git の中は `ls-files --others --ignored --exclude-standard --directory --no-empty-directory -z`、Git 管理外は `walkFiles` と同じ走査で除外したファイルとディレクトリを集める。`.git/` と `viewer.exclude` は除く。ツリー順に並べる
- `listIgnoredDir(root, dir, index)`: `dir` の直下を `readdir` で読む。ディレクトリは末尾に `/`、シンボリックリンクはファイルとして返す。`dir` が FileIndex のファイルを含む・ルートの外・ディレクトリでないときは `null`
- `FileIndex.isIgnoredFile(path)`: FileIndex に無く、除外 (`.git/`・`viewer.exclude`) に当たらず、realpath がルートの中のファイル
- テスト (一時リポジトリ): [gitignore_判定_調査.md](../research/gitignore_判定_調査.md) の `--ignored --directory` の各ケース、Git 管理外のネストした `.gitignore`、`viewer.exclude`、`dir` の不正な値、ルートの外を指すシンボリックリンク、`.git/index` の mtime が変わらない

### Task 4: ignored ファイルの配信

- `GET /api/tree/ignored` (`?dir=` 付き) を足す。Owner でなければ `403`、`dir` が不正なら `404`
- `GET /api/file` / `GET /api/raw`: Owner のときだけ、FileIndex に無いパスを `isIgnoredFile` で受け付ける
- テスト: Owner / 参加者それぞれの応答、ignored の Markdown と画像を Owner が読める、`../` とルートの外のシンボリックリンクは Owner でも `404`

### Task 5: スレッドとプロンプトの権限、再アンカー、監視

- スレッドの書き込み (作成・返信・コメントの編集と削除・Resolve・Reopen) で、対象のファイルが ignored ファイルで、Owner でなければ `403`。作成は Owner なら ignored ファイルにもできる
- `POST /api/prompt` は Owner でなければ `403`
- スレッドを送るとき (`GET /api/threads`、REST の応答、`thread.*` のイベント) に `ignored` を付ける
- 再アンカー: ignored ファイルのスレッドは、ファイルを `isIgnoredFile` を通して読む (今は FileIndex に無いと削除扱いになり、起動のたびに Outdated になる)
- 監視: `watchRoot` が一覧に無いパスも渡すようにし、ignored ファイルなら `file.changed` を Owner にだけ配り、スレッドがあれば再アンカーする
- テスト: 参加者の各書き込みが `403`、Owner は通る。参加者の `POST /api/prompt` が `403` で `exported_at` が記録されない。`ignored` の値。ignored ファイルを書き換えると Owner にだけ `file.changed` が届き、スレッドが追従する。再起動してもスレッドが Outdated にならない

### Task 6: 画面

- `ignoredFiles.ts`: `localStorage` の `reviewbuddy.ignoredFiles` (`shown` / `hidden`、不正なら `hidden`)
- ヘッダー: File Tree の開閉のボタンの右に目の形のボタン (Owner・Files の画面のみ)
- File Tree: ignored の項目を混ぜてツリー順に並べ、名前を `--muted` にする。畳んだディレクトリは展開時に読み込み (`Loading…`)、README.md は開かない。`tree.changed` と出し直しで取り直す
- ignored ファイルを開いている間は、プレゼンスの `view` で `null` を送る
- スレッド: `ignored` で Owner でなければ、Reply / Resolve / Reopen / Edit / Delete を出さない
- Review パネル: チェックボックス・"Copy prompt"・"Resolve copied threads" は Owner のみ。参加者は ignored ファイルのスレッドの項目をクリックできない
- テスト: 値の読み取り、畳んだディレクトリを含むツリーの組み立てと並び順 (`src/shared/tree.test.ts`)

### Task 7: E2E とドキュメント

- `test/e2e/ignored.test.ts` (一時リポジトリ、`isOwner` を差し替えて Owner と参加者の 2 つのブラウザ):
  - Owner がボタンで ignored ファイルを出す。`node_modules/` を展開して中を読み込む。ignored の Markdown を開いてコメントする。再読み込みしても表示の状態が残る
  - 参加者にはボタンと Copy prompt が出ず、ignored ファイルのスレッドが閲覧だけで見える
  - Owner が Copy prompt を使える
- 既存の E2E (`prompt.test.ts` など) は `127.0.0.1` / `localhost` で開くので Owner のまま通ることを確かめる
- README: Use に Owner と ignored ファイルの項目を足し、Copy a prompt が Owner だけになったことを書く。Security に Owner の判定と、TCP のまま転送する仕組みでは見分けられないことを書く
- 計画の完了条件と結果を更新し、v0.8.0 をリリースする ([リリース手順.md](../ops/リリース手順.md))

## リスク

| ID | リスク | 対策 |
|----|--------|------|
| R1 | TCP のまま転送する仕組み (`tailscale serve --tcp`、`ssh -R`) を通すと、参加者も Owner になる | README とセキュリティ.md に書く。案内する共有の方法は `tailscale serve` (HTTP) に限る |
| R2 | Owner が自分で ts.net の URL を開き、ボタンが出ないと戸惑う | README と CLI の説明で、Owner は `127.0.0.1` などの URL を開くよう案内する |
| R3 | ignored ファイルのスレッドで、コメントした行の内容 (`.env` の 1 行など) が参加者に見える | 仕様として受け入れる (ユーザーの判断)。コメントするのは Owner だけ |
| R4 | `.gitignore` の編集などで ignored かどうかが変わっても、画面の `ignored` は次に取り直すまで古い | 権限はサーバーで確かめるので、ずれてもボタンの出し方が変わるだけ。`tree.changed` でスレッドも取り直すかは実装時に決める |
| R5 | 監視が一覧に無いパスを渡すようになり、`bun install` などで `node_modules/` の変更が多いと、ignored ファイルの判定と Owner への `file.changed` が大量になる | 実装時に `bun install` 中の負荷を測る。多ければ、判定と配信をスレッドのあるパスと Owner が開いているパスに絞る (開いているパスは、プレゼンスの `view` とは別にサーバーへ伝える) |
| R6 | 既存の E2E は同じマシンのブラウザで開くため、全員 Owner になり、参加者の振る舞いを確かめられない | `ServerOptions.isOwner` で差し替える。判定そのものは Task 1・2 のテストで確かめる |
