## 目的

URL を知っているだけの人がファイルやコメントを見られないようにする。PIN は口頭やチャットなど、URL とは別の経路で伝える。

## スコープ

- PIN の生成 (一様な 6 桁) と表示 (`PIN: 482 913`)、ログイン (`POST /api/login`)、Cookie (`akapen_auth`、`HttpOnly; SameSite=Strict; Path=/`)
- 総当たり対策: 失敗は全体で 1 分あたり 5 回まで (`429`)、通算 20 回で以後のログインを拒否 (`403`、ターミナルに表示)
- `/api/*` と `/ws` に Cookie を要求する (`401`)。`POST /api/login` と `GET /api/health` は除く。`/api/health` はルートのパスを返さない
- 画面: Cookie が無いときは Nickname と PIN を一緒に入力する。サーバーの再起動で Cookie が無効になったら、もう一度入力する
- ドキュメント: セキュリティ・API・画面構成・CLI の設計書、README、Glossary

## 非スコープ

- PIN を無効にするオプション (`--no-pin`) — 必要になったら検討する
- Tailscale の ID ヘッダーによる自動ログイン (v2 候補)

## 完了条件

- [ ] `bun run verify` が通り、CI (macOS / Linux) も通る
- [x] PIN の生成・ログイン・失敗の回数の上限の単体テストがある
- [x] Cookie なしでは `/api/tree` などが `401`、WebSocket の upgrade が拒否される。`/api/health` はルートを返さない
- [x] E2E: 間違った PIN でエラーが出て、正しい PIN で使えるようになる。再読み込みしても PIN は聞かれない
- [x] ビルドしたバイナリが PIN を表示し、それでログインして使える (ビルドのテストと読み取り専用のテスト)
- [ ] v0.2.0 をリリースし、スモークテストが通る

## タスク分解

### Task 1: PIN とログインの判定

- **Files**: `src/auth.ts` / `src/auth.test.ts`
- **Produces**: `newPin(random?)` (6 桁、一様)、`formatPin(pin)` (`"482 913"`)、`class AccessGate` — `login(pin, now)` は `{ ok: true; token }` か `{ ok: false; status: 400 | 401 | 403 | 429; error }`、`isAuthorized(cookieHeader)`、`locked`
- **テストケース**: 6 桁で 0 埋め / 正しい PIN でトークン、Cookie で通る / 間違い・形式違い / 1 分あたり 5 回の上限と、1 分後の回復 / 通算 20 回で正しい PIN も拒否

### Task 2: サーバー

- **Files**: `src/server.ts` / `src/shared/api.ts` / `src/server-auth.test.ts` と既存のテスト
- `ServerOptions.access` (`AccessGate`)。渡さない場合は誰でも使える (テスト用。CLI は必ず渡す)
- `guard` に Cookie の確認を足し、`POST /api/login` を追加する。`/ws` の upgrade の前にも確認する。`Health` から `root` を外す

### Task 3: CLI と画面

- **Files**: `src/cli.ts` / `src/web/App.tsx` / `src/web/LoginDialog.tsx` / `src/web/api.ts` / `src/web/realtime.ts` / `test/e2e/login.test.ts` / `test/build.test.ts` / `test/read-only.test.ts`
- 起動時に `PIN: 482 913` を表示する。ログインの画面は Nickname (保存済みなら入力済み) と PIN の 2 つの欄。`inputmode="numeric"`、空白は無視する
- WebSocket が切れたときに `/api/session` が `401` なら (サーバーの再起動)、ログインの画面に戻す

### Task 4: ドキュメントとリリース

- 設計書・README・Glossary を更新し、v0.2.0 をリリースする ([リリース手順.md](../ops/リリース手順.md))
