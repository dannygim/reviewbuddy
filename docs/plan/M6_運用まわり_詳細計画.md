## 目的

- 対象の要件: F13 (セッションの終了と削除) / A1 (ファイルの監視とライブ更新) / A2 (コメント位置の追従と Outdated)、設定ファイル
- 前提の確認 (2026-10-23): macOS の Bun 1.4.4 で `fs.watch(root, { recursive: true })` は、ネストした新しいディレクトリも含めてルートからの相対パスでイベントを届ける (内容の変更も `rename` で届く)。Linux はウォッチャーのテストを CI で動かして確かめる

## スコープ

- `config.toml` の読み込みと検証、優先順位 (フラグ > 環境変数 > ファイル > 既定値)、`akapen config init / path / show`
- 設定の反映: `server.host` / `server.port` (明示扱い) / `server.open_browser` (`--open` / `--no-open`) / `server.allowed_hosts` / `viewer.max_highlight_bytes` / `viewer.exclude` / `prompt.*` / `retention.*`
- `akapen session ls [--all] / end [dir|id] / reopen <id> / rm <id...> / prune [--dry-run]`
- 起動時の自動処理 (idle の active を終了、期限を過ぎた ended を削除、ルートが無いものを終了) と 1 行のログ
- UI の End session (確認のモーダル、`POST /api/session/end`、`session.ended` の配信、read-only のバナー)。CLI の `session end` で終わったセッションも、起動中のサーバーが数秒以内に気づいて read-only になる
- ファイルの監視 (`--no-watch`): `file.changed` / `tree.changed`、開いているファイルの取り直し
- 再アンカー: ファイルの変更時と起動時。`thread.updated` で配信

## 非スコープ

- 終了したセッションを起動中のサーバーで再開すること (`session reopen` の後はサーバーを起動し直す)

## 完了条件

- [ ] `bun run verify` が通り、CI (macOS / Linux) も通る
- [ ] 設定の優先順位と検証のエラー (キーのパス付き) がテストで確認されている。`config init` は既存のファイルを上書きしない
- [ ] prune の判定 (idle / ended の日数、`0` で無効、起動中は対象外、ルートが消えたセッション) が単体テストで固まっている
- [ ] UI の End で全員の画面が read-only になる (E2E)
- [ ] ファイルを書き換えると開いている画面が更新され、ファイルを足すとツリーに出る (E2E。macOS と Linux)
- [ ] 再アンカー: 行の挿入・削除・対象の行の編集・削除・同じ内容が 2 か所・内容が戻る、の各ケースが単体テストで通る

## タスク分解

### Task 1: 設定ファイル

- **Files**: `src/config/config.ts` / `src/config/template.ts` / `src/config/config.test.ts` / `src/args.ts` / `src/cli.ts` / `src/server.ts` / `src/shared/api.ts`
- **Produces**: `type Config`、`loadConfig(home, env): { config; warnings; portExplicit }` (`ConfigError` はキーのパス付き)、`CONFIG_TEMPLATE` (コメント付き)、`configToToml(config)`
- `args.ts` の `serve` は `host` / `port` を省略可能にし、既定値の解決を CLI 側へ移す。`--open` / `--no-open` / `--no-watch` を足す。`config` サブコマンド
- サーバーには `allowedHosts` / `maxHighlightBytes` / `prompt` / `exclude` を設定から渡す。`GET /api/session` に `resolveOnCopy` と `prompt` を足す (Review パネルの既定と、read-only のときの整形に使う)
- **テストケース**: ファイルが無い → 既定値 / 優先順位 / 未知のキーは警告 / 型・範囲の違いはエラー / `config init` が上書きしない / 雛形が読めて既定値と一致 / 環境変数の不正な値

### Task 2: セッションの運用

- **Files**: `src/session/retention.ts` / `src/session/commands.ts` / テスト / `src/args.ts` / `src/cli.ts`
- **Produces**: `planPrune(sessions, now, retention, { isRunning, rootExists }): { end: SessionMeta[]; remove: SessionMeta[] }` (純粋関数)、`applyPrune(home, plan)`、`session` の各コマンド
- **テストケース**: idle の境界 / ended の境界 / `0` で無効 / 起動中は対象外 / ルートが消えたもの / `ls` の表示 / `end` を ID とディレクトリの両方で / `reopen` は同じルートに active があると失敗 / `rm` は起動中を拒否

### Task 3: セッションの終了

- **Files**: `src/server.ts` / `src/web/App.tsx` / `src/web/EndSessionDialog.tsx` / `test/e2e/end-session.test.ts`
- `POST /api/session/end` で `session.json` を `ended` にし、サーバーを read-only にして `session.ended` を配信する。サーバーは 5 秒ごとに `session.json` を読み、CLI で終わった場合も同じ扱いにする
- クライアントは `session.ended` でバナーを出し、入力欄と「+」を隠す
- **E2E**: 2 つのブラウザ → 片方で End → 両方に read-only のバナー

### Task 4: ファイルの監視

- **Files**: `src/watch/watcher.ts` / `src/watch/watcher.test.ts` / `src/server.ts` / `src/web/Viewer.tsx` / `src/web/App.tsx` / `test/e2e/watch.test.ts`
- 200ms のデバウンスで、一覧に含まれるパスは `file.changed`、それ以外は FileIndex を作り直して変わったら `tree.changed`。`.git/` の中のイベントは作り直しだけ
- クライアントは開いているファイルの `file.changed` で取り直す (スクロール位置は保つ)
- **テストケース**: 変更・追加・削除・ネストしたディレクトリの追加・`.gitignore` の対象は通知しない

### Task 5: 再アンカー

- **Files**: `src/review/reanchor.ts` / `src/review/reanchor.test.ts` / `src/review/store.ts` / `src/server.ts`
- **Produces**: `reanchor(thread, lines | null): { startLine; endLine; outdated }` (純粋関数)、`ReviewStore.reanchorFile(path, text | null): Thread[]` (変わったスレッドを返す)
- ファイルの変更時 (Task 4) と起動時に実行し、変わったスレッドを `thread.updated` で配信する
- **テストケース**: [データモデル.md](../design/データモデル.md) のテスト観点のすべて

## リスク

| # | リスク | 対応 |
|---|--------|------|
| R1 | Linux で `fs.watch` の recursive が使えない | CI のウォッチャーのテストで確かめる。だめならディレクトリごとに監視する |
| R2 | 大きなリポジトリでイベントが多い (`node_modules` など) | デバウンスでまとめ、一覧に無いパスは FileIndex の作り直し 1 回にまとめる |
| R3 | 再アンカーの誤り | 完全一致だけを使い、迷ったら Outdated に倒す |
