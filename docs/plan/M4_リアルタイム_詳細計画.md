**目的: スレッドの変更を WebSocket で参加者全員に即時に届け、誰がどのファイルを見ているかを表示し、Markdown の Preview 上でもブロック単位でコメントできるようにする。**

- 設計: [API.md](../design/API.md) / [セキュリティ.md](../design/セキュリティ.md) / [画面構成.md](../design/画面構成.md) / [Markdown_Preview.md](../design/Markdown_Preview.md)

## 目的

- 対象の要件: F9 (Preview 表示でのブロックコメント) / F10 (即時の配信) / A4 (プレゼンス)
- セキュリティ: WebSocket の upgrade にトークンと `Origin` の検証を入れる

## スコープ

- `GET /ws?token=` の upgrade (Host・トークン・`Origin` の検証)、トピック `review` への配信
- イベントの型 (`src/shared/events.ts`): `presence.changed` / `thread.created` / `thread.updated` / `thread.deleted`。M6 で使う `file.changed` / `tree.changed` / `session.ended` も型だけ定義する
- 書き込みの API の後に、サーバーがイベントを配信する
- クライアント: 接続・`hello` / `view` の送信・イベントの適用・再接続 (間隔を延ばしながら最大 10 秒、つながったら取り直す)
- プレゼンス: ヘッダーに接続中の参加者、File Tree に閲覧中の参加者の頭文字
- Preview のブロックコメント: ホバーで「+」、クリックで最も内側の `data-src-*` 要素、Shift+クリックで複数のブロックに広げる。スレッドと入力欄をブロックの直下に出す

## 非スコープ

- `file.changed` / `tree.changed` / `session.ended` の送信 → M6
- `tailscale serve` 経由の手動確認は、本計画では行えない (tailnet の設定が要る)。README の案内に残し、利用者の環境で確かめる

## 設計からの変更

- [API.md](../design/API.md) の `comment.created` / `comment.updated` / `comment.deleted` は使わない。REST の応答と同じく、コメントの変更もスレッド全体を `thread.updated` で送る (クライアントの処理が 1 種類で済むため)。設計書も更新する

## タスク分解

### Task 1: イベントの型と WebSocket のサーバー側

- **Files**: `src/shared/events.ts` / `src/realtime/hub.ts` / `src/server.ts` / `src/review/routes.ts` / `src/realtime/hub.test.ts`
- **Produces**:
  - `type ServerEvent` / `type ClientMessage` / `type Participant` (`clientId` / `nickname` / `path`)
  - `isAllowedOrigin(origin: string | null, host: string | null): boolean` — `Origin` が無い (ブラウザ以外) か、そのホストが `Host` と一致するか、`.ts.net` で終わる
  - Hub: 接続の集合、`hello` / `view` の受信、`presence.changed` の配信、`publish(event)`
  - `reviewRoutes` に `publish` を渡し、書き込みの後に配信する
- **テストケース**: 2 クライアントでのプレゼンスとスレッドの配信 / 10 クライアント / トークンなし・不一致・`Origin` 違い・`Host` 違いの拒否 / 切断でプレゼンスから消える

### Task 2: クライアントの接続とプレゼンス

- **Files**: `src/web/realtime.ts` / `src/web/presence.ts` / `src/web/App.tsx` / `src/web/FileTree.tsx` / `src/web/api.ts`
- 接続して `hello` を送り、`docPath` が変わるたびに `view` を送る。スレッドのイベントは `threadStore` に適用する。切れたら再接続し、つながったら `GET /api/threads` と `GET /api/tree` で取り直す
- ヘッダー: 参加者の Nickname (自分を先頭に、`client_id` で重複を除く)。File Tree: 他の参加者が開いているファイルに頭文字の丸 (ホバーで Nickname)

### Task 3: Preview のブロックコメント

- **Files**: `src/web/MarkdownPreview.tsx` / `src/web/blocks.ts` (DOM の補助) / `src/web/Viewer.tsx` / `src/web/styles.css`
- ホバーした位置から最も内側の `[data-src-start]` を探し、右上に「+」を出す。クリックでそのブロックを選び、Shift+クリックで選択の範囲を広げる (開始行の最小〜終了行の最大)
- 入力欄とスレッドは、`createPortal` でブロックの直後に差し込んだ入れ物に描く (`tr` の後には `tr`、`li` の中には末尾に入れる)。スレッドは `endLine` を含む最も内側のブロックの後に置き、当てはまるブロックが無いものは末尾にまとめる
- 入力欄の表示はマウスのボタンを離した後に行う (M3 で分かったレイアウトのずれの問題を避ける)

### Task 4: E2E

- **Files**: `test/e2e/realtime.test.ts`
- 2 つの `Bun.WebView` で同じファイルを開き、片方でコメント → もう片方に出る。ヘッダーに 2 人
- Preview で段落の「+」(ホバーは `mousemove` を送って再現) → コメント → 段落の直下に出る → Source タブで該当行の下にも出る
