## 目的

- 配色を OS 任せにせず、参加者がブラウザごとに Light / Dark / System を選べるようにする (非機能要件の「UI」)
- File Tree で、どのファイルにどの状態のスレッドがあるかを一目で分かるようにし、ディレクトリの README.md にすぐ辿り着けるようにする (F4)
- ログイン画面に reviewbuddy のロゴを出す

## スコープ

- CSS の色の変数を `light-dark()` で 1 か所に定義し直し、`prefers-color-scheme` のメディアクエリをなくす。Shiki の出力を `defaultColor: 'light-dark()'` にする
- Display mode の保存 (`localStorage` の `reviewbuddy.displayMode`)・反映 (`<html data-display-mode>`)・ヘッダーの切り替えのメニュー (Popover API)
- Display mode が変わったときの Mermaid の図の描き直し
- File Tree: ファイルの吹き出しのアイコン (Open は件数付き、Resolved だけは線)、折りたたんだディレクトリの点
- File Tree: 折りたたんだディレクトリを展開したときに、直下の README.md を開く
- ログインのモーダルのロゴ (2 つの吹き出しのマーク + "review**buddy**")
- README (利用者向け) の追記、v0.4.0 のリリース

## 非スコープ

- ヘッダーや favicon へのロゴの表示 — 依頼の範囲外。必要になったら追加する
- Display mode をサーバーに保存して参加者間で共有すること — ブラウザごとの設定とする
- 書きかけのコメントがある状態でファイルを移るときの警告 — ファイルのクリックでも同じことが起きる既存の挙動で、今回は扱わない
- `README`・`README.rst` など `.md` 以外の README

## 全体の制約

- 依存を増やさない (ADR-0001)。アイコンとロゴは SVG を直接書く
- UI の文言は英語 (`Light` / `Dark` / `System`、`Display mode: <モード>`、`<n> open threads`、`Resolved threads only`、`Open threads inside`)
- CSS で `prefers-color-scheme` のメディアクエリを使わない。配色の判定が要る JS は `useColorScheme()` を使う
- 対象ディレクトリには書き込まない。Display mode はブラウザの `localStorage` だけに保存する
- コードは周りに合わせる (コメントの量、命名、`useSyncExternalStore` のストアの書き方は `src/web/store.ts`)。整形は `bun run format`
- ヘッドレスのブラウザ (`Bun.WebView`) は OS がライトとして動く。E2E で System はライトの色を期待する

- 手作業の確認 (Chrome のバックエンドで OS の配色と回線をまねた。[Display_mode_調査.md](../research/Display_mode_調査.md)):
  - R1: OS がダークのときに Light を選ぶとライトになる。WebKit (Safari) は OS の配色をまねる手段が無く、未確認
  - R2: 手元では差が出なかったが、遅い回線ではバンドルが届くまで反対の配色が見えた。計画の対応どおり、`index.html` の `<head>` に保存値を反映するインラインの script を置いた (`c6554ac`)。同じ条件で、属性が最初の描画より前に付くようになった
  - Light / Dark の画面写真で、コード、Markdown、Mermaid、メニュー、File Tree のアイコンと点、ログインのモーダルに崩れが無いことを見た
- 計画から変えた点:
  - `src/web/index.html` に上の script を足した (R2 の対応。ファイルの構成の表に無かった)
  - `Bun.WebView` の `press()` は ArrowDown / Enter をキーのイベントとして送らない。メニューの E2E は、ArrowDown を `KeyboardEvent` で送り、Enter はフォーカスした項目の `click()` で代えた (Enter のボタンの動きはブラウザの標準)。Esc は `press()` で送れた
  - WebKit はクリックしたボタンにフォーカスを移さないため、Esc でメニューを閉じてもボタンにフォーカスが戻らなかった。計画に書いた予備策どおり、`onToggle` で閉じたときに戻す
  - Mermaid の E2E は、SVG の `<style>` の比べ方を変えた。`<style>` には描くたびに変わる SVG の id が入り、テーマが同じでも中身が変わってしまうため、id を除いて比べる
