# M3 セッションとコメント 詳細計画

**目的: コメントをセッション単位で `~/.config/akapen/` に永続化し、Source 表示で行を選んでスレッドを作り、リプライ・編集・削除・Resolve できるようにする。**

- 上位計画: [akapen_実装計画.md](./akapen_実装計画.md) の M3
- 設計: [保存先とセッション.md](../design/保存先とセッション.md) / [データモデル.md](../design/データモデル.md) / [API.md](../design/API.md) / [セキュリティ.md](../design/セキュリティ.md) / [画面構成.md](../design/画面構成.md) / [CLI_仕様.md](../design/CLI_仕様.md)
- 作成日: 2026-10-23
- 書き方: M1 と同じく、コードの全文は載せない

***

## 目的

- 対象の要件: F3 (Nickname) / F9 (Source 表示での行の選択) / F10 (REST まで) / F11 (永続化)
- セキュリティ: 書き込み API のトークンと `Content-Type` の検証を入れる (WebSocket のトークンと `Origin` は M4)

## スコープ

- akapen のホームの解決 (`AKAPEN_HOME` > `$XDG_CONFIG_HOME/akapen` > `~/.config/akapen`)、パーミッション、`sessions/.gitignore`
- `session.json` の作成・検索・再開、`--new` / `--session <id>`、終了したセッションの read-only
- `server.lock` による多重起動の防止
- `review.db` のスキーマとマイグレーション、スレッドとコメントの操作
- REST API (`GET /api/session`、`GET/POST /api/threads`、リプライ・編集・削除・Resolve / Reopen)、`/api/health` にセッション ID を足す
- `lastActiveAt` の更新 (1 分に 1 回まで)
- SPA: Nickname のモーダル、`client_id`、Source 表示の行の選択 (クリック / Shift+クリック / ドラッグ)、行の直下のスレッドとコメントの入力欄、File Tree の未解決数のバッジ、read-only のバナー

## 非スコープ

- 他の参加者への即時の反映 (WebSocket)、プレゼンス、Preview 表示でのブロックコメントとスレッドの表示 → M4 (M3 では自分の操作の結果だけが画面に反映され、他の人の操作はファイルを開き直すと見える)
- セッションの終了 (UI の End / `akapen session ...`)、自動の終了と削除、`config.toml` → M6 (M3 では `--session` で ended を開いたときの read-only だけを扱う)
- 再アンカーと Outdated → M6

## 完了条件

- [x] `bun run verify` が通り、CI (macOS / Linux) も通る
- [x] サーバーを再起動しても、同じルートならスレッドが残っている。`--new` では空のセッションになり、前のセッションは `ended` になる
- [x] 同じルートで 2 回起動すると、2 回目は既存の URL を出して終了コード 0 で終わる。プロセスが死んだ後のロックは掃除されて起動できる
- [x] 他人の `client_id` のコメントを編集・削除できない (`403`)。トークンの無い書き込みは `403`、read-only のセッションへの書き込みは `409`
- [x] 作成したディレクトリとファイルのパーミッションが `0700` / `0600`
- [x] E2E: Nickname を入れ、Source 表示で 2〜3 行目を選んでコメントし、リプライ・Resolve ができる。再読み込みしても残っていて、ツリーにバッジが出る

## タスク分解

### Task 1: akapen のホーム

- **Files**: `src/session/home.ts` / テスト
- **Produces**: `akapenHome(env?: Record<string, string | undefined>): string`、`ensurePrivateDir(path): void` (無ければ `0700` で作る)、`writePrivateFile(path, content): void` (一時ファイルに `0600` で書いて rename する)、`ensureSessionsDir(home): string` (`sessions/` と `sessions/.gitignore` を作る)
- **テストケース**: 環境変数の優先順位 / パーミッション / `.gitignore` の中身が `*` / 既存のファイルを上書きするときも `0600`

### Task 2: セッションのメタ情報

- **Files**: `src/session/session.ts` / テスト
- **Produces**:
  - `type SessionMeta` (`schemaVersion` / `id` / `root` / `status` / `createdAt` / `lastActiveAt` / `endedAt` / `appVersion`)
  - `newSessionId(root, now, random): string` — `YYYYMMDD-HHmm-<ルート名>-<16 進 4 桁>` (ルート名は `[a-z0-9-]` に正規化して 32 文字まで、空なら `root`)
  - `listSessions(home): SessionMeta[]` (壊れた `session.json` は飛ばす)、`readSession(home, id)`、`writeSession(home, meta)`
  - `openSession(home, root, { fresh, id }, now): { meta, readOnly }` — 同じ root の active を再開 / 無ければ作る / `fresh` なら既存の active を `ended` にして作る / `id` なら指定したものを開く (`ended` なら `readOnly`、見つからなければエラー)
  - `touchSession(home, meta, now)` — 最後の更新から 1 分以上たっていれば `lastActiveAt` を書く
- **テストケース**: ID の形式と正規化 / 作成 → 再開 / 別のルートは別のセッション / `fresh` / `id` で active・ended・存在しないもの / 壊れた JSON を飛ばす / `touchSession` の間引き

### Task 3: 多重起動の防止

- **Files**: `src/session/lock.ts` / テスト
- **Produces**: `type LockInfo = { pid; host; port; startedAt }`、`readLock(dir)`、`writeLock(dir, info)`、`removeLock(dir)`、`isProcessAlive(pid)`、`findRunningServer(dir, sessionId): Promise<string | null>` — ロックの pid が生きていて `/api/health` が同じセッション ID を返せば、その URL を返す。違えばロックを消して `null`
- **テストケース**: ロックが無い / 死んだ pid / 生きているが別のセッション ID を返す / 同じセッション ID を返す (テスト内でサーバーを立てる)

### Task 4: レビューの DB

- **Files**: `src/review/db.ts` / `src/review/ulid.ts` / `src/review/store.ts` とテスト
- **Produces**:
  - `openReviewDb(path): Database` — `0600` で作り、WAL / `foreign_keys` / `busy_timeout = 5000`、`user_version` によるマイグレーション
  - `ulid(now?): string` — 時系列で並ぶ 26 文字の ID
  - `class ReviewStore` — `listThreads(path?)` / `getThread(id)` / `createThread(input)` / `addComment(threadId, input)` / `editComment(id, clientId, body)` / `deleteComment(id, clientId)` (元コメントはリプライが無いときだけ消せて、スレッドごと消える) / `resolve(id, by)` / `reopen(id)`。失敗は `ReviewError(status, message)` で投げる (`404` / `403` / `409`)
  - `Thread` / `Comment` の型を `src/shared/api.ts` に置く (行番号・パスは設計どおり)
- **テストケース**: スキーマと `user_version` / スレッドの作成と一覧 (パス → 開始行の順) / リプライの順序 / 他人のコメントの編集・削除が `403` / リプライのある元コメントの削除が `409` / 元コメントだけのスレッドの削除でスレッドが消える / Resolve と Reopen / `ulid` の単調性

### Task 5: REST API とサーバーの組み立て

- **Files**: `src/review/anchor.ts` / `src/server.ts` / `src/shared/api.ts` / `src/cli.ts` / `src/args.ts` とテスト
- **Produces**:
  - `anchorFor(text, startLine, endLine): { anchorText; fileSha }` — 行範囲を検証し (1 ≤ start ≤ end ≤ 行数)、元の行を切り出す
  - サーバーの `options` に `session: { meta; readOnly; token; store: ReviewStore; touch(): void }` を足す
  - ルート: `GET /api/session` / `GET` `POST /api/threads` / `POST /api/threads/:id/comments` / `PATCH` `DELETE /api/comments/:id` / `POST /api/threads/:id/resolve` / `POST /api/threads/:id/reopen`。`/api/health` にセッション ID
  - 書き込みの共通の検証: Host → `X-Akapen-Token` (`403`) → `Content-Type: application/json` (`415`) → read-only (`409`) → 入力の検証 (`400`。本文は 1〜20,000 文字、Nickname は 1〜50 文字)
  - CLI: `--new` / `--session <id>` を足す。起動の流れは「ルートの解決 → セッションを開く → 動いているサーバーがあれば URL を出して終了 → FileIndex → サーバーの起動 → ロックを書く」。終了時 (SIGINT / SIGTERM) にロックを消す
- **テストケース**: 各ルートの正常系 / トークンなし `403` / `Content-Type` 違い `415` / read-only `409` / 一覧に無いパス・範囲外の行 `400` / 存在しないスレッド `404` / CLI の多重起動 (同じ `AKAPEN_HOME` で 2 回起動すると 2 回目が URL を出して 0 で終わる)

### Task 6: SPA のコメント

- **Files**: `src/web/store.ts` (スレッドのストア。M4 で WebSocket のイベントもここに流す) / `src/web/identity.ts` (Nickname と `client_id`) / `src/web/api.ts` / `src/web/App.tsx` / `src/web/Viewer.tsx` / `src/web/CodeView.tsx` / `src/web/Thread.tsx` / `src/web/Composer.tsx` / `src/web/NicknameDialog.tsx` / `src/web/FileTree.tsx` / `src/web/styles.css` / `test/e2e/comments.test.ts`
- 行の選択: 行番号のクリック (1 行) / Shift+クリック (範囲を広げる) / 行番号の上のドラッグ。選んだ行を強調し、最後の行の直下に入力欄 (Cmd/Ctrl+Enter で送信、Esc で閉じる)
- スレッド: `endLine` の行の直下に出す。コメントごとに Nickname・相対時刻・本文 (プレーンテキスト、改行を保持、URL だけリンク)。Reply / Resolve / Reopen、自分のコメントに Edit / Delete。Resolved は折りたたむ
- バッジ: ファイルごとの未解決のスレッドの数
- **E2E**: 上の完了条件の流れ

## リスク

| # | リスク | 対応 |
|---|--------|------|
| R1 | M4 までは他の人の操作が即時に見えない | 計画どおり。ファイルを開き直すと取り直す |
| R2 | `client_id` を全員に返すため、なりすましで他人のコメントを編集できる | 設計どおりの信頼ベースの制御として受け入れる ([データモデル.md](../design/データモデル.md)) |
| R3 | SIGKILL などでロックが残る | 次の起動で pid の生存と `/api/health` を確かめて掃除する |
| R4 | テストが実際の `~/.config/akapen` を汚す | テストと E2E は必ず一時ディレクトリの `AKAPEN_HOME` を使う |

## 実装で分かったこと

- 行番号のクリックで入力欄が開くと、その下の行が押し下げられる。マウスのボタンを押している間に入力欄を消したり動かしたりすると、ポインタの下に別の行が来て、ドラッグとして範囲が広がってしまう (9 行目を選んでから 10 行目を Shift+クリックすると 9〜18 行目になった)。入力欄の表示と移動は `mouseup` の後に行い、押している間は行の強調だけを変える。E2E (`test/e2e/comments.test.ts`) で 30 行のファイルを使って再現と修正を確かめている
- `--session` を指定したときはセッションの `root` を開き、ディレクトリの引数や `--new` とは併用できないことにした ([CLI_仕様.md](../design/CLI_仕様.md))
- 多重起動のときに既存の URL をそのまま出すため、`server.lock` に `url` も記録する
