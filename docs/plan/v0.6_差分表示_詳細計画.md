# v0.6 差分表示 詳細計画

**目的: 未コミットの変更を GitHub の Files changed と同じ形で見せる Changes 画面 (A5) を作り、v0.6.0 として出す。**

- 設計: [差分表示.md](../design/差分表示.md) / [画面構成.md](../design/画面構成.md) (Changes 画面) / [API.md](../design/API.md) / [要件.md](../design/要件.md) (A5)
- 調査: [git_差分_調査.md](../research/git_差分_調査.md)
- 作成日: 2026-11-05
- 書き方: v0.5 と同じく、コードの全文は載せない (計画を書いてすぐ同じセッションで実装するため)

***

## 目的

- Agent が直した結果を、ファイルを 1 つずつ開かずに、変更の部分だけ確かめられるようにする
- 変更を見ながら、その場で変更後の行にコメントし、今までと同じくプロンプトにして Agent に返せるようにする
- Markdown の設計書の変更も、レンダリングした状態で確かめられるようにする

## スコープ

- サーバー: 変更の一覧 (`GET /api/changes`)、1 ファイルの差分 (`GET /api/diff`)、`changes.changed` の配信
- 自前の Myers (行の中の単語、Markdown のブロック、HTML の単語の比較に使う)
- 単語の強調付きのハイライト、Markdown のレンダリングした差分
- クライアント: `Files | Changes` の切り替え、Changes 画面 (ツリー、カード、行の展開、Viewed、Comment Pane)
- ドキュメント (要件・設計・調査・API・画面・用語) と README の追記、v0.6.0 のリリース

## 非スコープ

- 削除された行へのコメント — 今のスレッドは今のファイルの行にひも付くため (ユーザーの判断)
- コミットしたスレッドを自動で Outdated にすること — 参加者が Resolve する (ユーザーの判断)
- コミット単位・ブランチ単位の差分、ステージ済み / 未ステージの区別
- 画像の差分の並べての表示、Split (左右に並べる) 表示
- Viewed の参加者間の共有

## 全体の制約

- 依存を増やさない (ADR-0001)
- git は `git --no-optional-locks -C <root>` で plumbing (`diff-index` / `cat-file` / `ls-files` / `rev-parse`) だけを使う。porcelain の `git diff` は `.git/index` を書き換えるので使わない
- 対象ディレクトリに書き込まない。Viewed はブラウザの `localStorage` だけに保存する
- UI の文言は英語

## タスク分解

Task 1〜6 はサーバー、Task 7〜10 はクライアント。各タスクはテストを先に書く。

### Task 1: Myers と単語の範囲

- `diffSequences(a, b, equals?, maxCost?)` は、同じ / 削除 / 追加 の連続を返す。コストが `maxCost` を超えたら全削除 + 全追加を返す
- `wordRanges(oldLine, newLine)` は、両方の行の違う文字の範囲を返す。共通の空白でないトークンが無ければ `null`
- テスト: 空の列、同じ列、先頭 / 末尾 / 途中の挿入と削除、`maxCost` の打ち切り、単語の一部違い、空白だけの違い、共通の無い組

### Task 2: ハイライトの強調

- `highlightLines(lines, lang, marks?)` に、行ごとの範囲の配列を渡せるようにする。トークンを範囲の境目で分け、範囲の中を `<span class="diff-word">` で囲む。`text` の言語と、ハイライトしないとき (`escapeLines`) も同じ
- テスト: 範囲がトークンをまたぐ、`<` などの特殊文字、範囲なしは今と同じ出力

### Task 3: 変更の一覧

- `listChanges(root, index)` が `ChangesResponse` を返す ([差分表示.md](../design/差分表示.md) の規則)
- テスト (一時リポジトリ): 変更・ステージ済みの追加・未追跡・削除・`git mv`・`touch` だけ・`.gitignore`・バイナリ・サブディレクトリのルート・HEAD 無し・Git 管理外、`.git/index` の mtime が変わらない

### Task 4: 1 ファイルの差分

- hunk のヘッダーの読み取り (`parseHunkHeaders`) と `renderDiff(root, change, options)`
- テスト: ヘッダーの省略形・行数 0・関数名、変更 / 追加 / 削除 / 名前の変更の各ファイル、バイナリ、単語の強調が HTML に入る

### Task 5: レンダリングした差分

- `markdown.ts` から、最上位のブロックに分けたトークンとレンダリングの関数を出す。`renderMarkdown` の出力は変えない (既存のテストで確かめる)
- `renderMarkdownDiff(oldSource, newSource, options)` と HTML の単語の比較
- テスト: 段落の追加 / 削除 / 単語の違い、見出しのレベル違い (組にしない)、リストの項目の追加 / 削除 / 変更、表の変更、変更前の側に `data-src-*` が無い、変更後の側に残る

### Task 6: サーバー

- `GET /api/changes` (監視するときはキャッシュ)、`GET /api/diff?path=`、監視のたびに `changes.changed`
- テスト: 応答の形、一覧に無いパスの 404、ファイルの書き換え・コミットで `changes.changed` が届く

### Task 7: ルートと Viewed

- `useChangesRoute()` / `openChanges()`、`viewed.ts` (`parseViewed`、`useViewed(sessionId, changes)`)
- テスト: `parseViewed` の不正な値、`version` が違えば Viewed でない

### Task 8: 差分の行

- `diffRows(changes, oldCount, newCount, revealed)` が、hunk のヘッダー / 変わらない行 / 削除 / 追加 の行の列を返す
- テスト: 前後 3 行、間が 6 行以下でまとまる、先頭と末尾、20 行ずつの展開と全部の展開

### Task 9: Changes 画面

- `DiffView` (表、行の選択、Comment Pane)、`ChangesView` (上部、カード、Viewed、Load diff、Markdown の切り替え)、`ChangesTree`、`App` の切り替えとデータの取得、スタイル

### Task 10: E2E とドキュメント

- `test/e2e/changes.test.ts`: 一時リポジトリで、切り替え・ツリー・Viewed と再読み込み・追加行へのコメントの行番号・レンダリングした差分・ファイルの書き換えでの更新
- README の追記、計画の完了条件の更新

## リスク

| ID | リスク | 対策 |
|----|--------|------|
| R1 | 変更が多いと、一覧のたびに全部の変更後のファイルを読む (`version` のため) | 監視するときは一覧をキャッシュし、全ブラウザで共有する。重ければ mtime と size に置き換える |
| R2 | レンダリングした差分の組み方が、大きく書き換えた文書で読みにくい | 組にするのは同じ種類のブロックだけにし、それ以外は上下に並べる。使ってみて調整する |
| R3 | 多くのカードがそれぞれ Comment Pane を持ち、位置の計算が重くなる | 閉じたカードは差分を描かない。大きな差分は `Load diff` まで描かない |
| R4 | Linux の CI に git のユーザー設定が無い | テストのリポジトリでは `-c user.name=... -c user.email=...` を付けてコミットする |

## 結果 (2026-11-05)

- v0.6.0 をリリースした。PR #1 を rebase でマージし、`main` の CI (macOS / Linux) が通った後にタグを push した。リリースのワークフローはスモークテスト (macOS / Linux) まで通った ([実行](https://github.com/dannygim/reviewbuddy/actions/runs/42001604626))。Release に 3 つのアーカイブと `checksums.txt` が載り、手元の Mac で `mise exec github:dannygim/reviewbuddy@0.6.0 -- reviewbuddy --version` が `0.6.0` を出した (`com.apple.quarantine` なし)
- Task 1〜10 を実装した。`bun run verify` (403 件)、Chrome のバックエンドでの E2E (`REVIEWBUDDY_E2E_BACKEND=chrome`、37 件)、`bun run build` の後の `test/build.test.ts` と `test/read-only.test.ts` が通った
- PR #1 への Copilot のレビュー (10 件) はすべて直した ([差分表示.md](../design/差分表示.md) に反映):
  - シンボリックリンクはリンク先のパスで比べ、リンク先を読まない (ルートの外の内容が行数・ハッシュに出ていた)
  - Myers の探索のメモリを `maxCost` で抑える (20,000 トークンどうし・上限 2,000 で 663MB 使っていた)
  - `git rm --cached` で残したファイルを、削除と追加の 2 つでなく、HEAD と比べた 1 つの変更にする
  - `version` に HEAD の blob を入れる (HEAD の側だけが変わったときに Viewed が外れなかった)
  - 差分の HEAD を 1 つのコミットに決め、パスを `:(literal)` で渡し、Git の hunk が読んだ行と合わなければ自前の Myers で比べる
  - 引用符の中に `>` がある属性のタグを分けない
  - リンクされた worktree・リポジトリの中のディレクトリをルートにしたとき、ルートの外の Git のディレクトリも監視する (コミットしても一覧が更新されなかった)
  - 最初の変更の上の行の展開で、hunk のヘッダーより上に行が出ていた
- ビルドしたバイナリを、一時リポジトリのリンクされた worktree に向けて起動し、`Bun.WebView` (WebKit、1280×900、Light) で開いた。Changes 画面に 2 ファイルが出て、Markdown のレンダリングした差分の `<del>` / `<ins>`、コードの差分の単語の強調が出た。worktree でコミットすると一覧が空になった
- リリースのコミットの CI で、macOS だけ `test/e2e/viewer.test.ts` の `opens a file from the tree and reflects it in the URL` が 1 回失敗した (`src/main.ts` が押せる状態にならずタイムアウト)。同じアプリのコードは macOS の CI で 3 回通り、手元でも 8 回続けて通ったため、失敗したジョブだけを再実行して通した。原因は調べていない。また出たら調べる
- 見た目は、実装中に `Bun.WebView` のスクリーンショット (Light / Dark) で確かめた。未確認: Safari での手作業の確認
